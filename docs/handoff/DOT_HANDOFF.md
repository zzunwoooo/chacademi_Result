# dot 클라우드와 호스팅 SSH 작업 인수인계

이 문서는 이전 작업을 수행하던 Codex가 사용자의 명시적 지시와 확인된 환경 정보를 dot에 전달하기 위해 작성한 인수인계 문서다. 기준일은 2026년 10월 1일, 시간대는 Asia/Seoul이다.

사용자는 일본에서 노트북을 사용한다. 작업 중 노트북의 네트워크와 메모리를 많이 사용하면 다른 일을 하기 어려우므로, 노트북을 작업 실행 경로에서 빼려 한다. **기본 수행자는 dot 본인이다. dot은 자신의 클라우드 환경에서 직접 코드를 작성하고, 그 클라우드에서 시작한 SSH로 호스팅 컴퓨터의 파일과 서버 설정을 수정한다. 사용자의 명시적 허가 없이 Codex 작업을 생성하거나 실행하거나 기존 작업에 지시하지 않는다.** 필요한 파일 설치와 빌드, 테스트, 실행은 호스팅 컴퓨터에서 처리한다.

**이번 인수인계는 작업 환경에만 관한 것이다.** 프로젝트의 서버 기능, 게임 콘텐츠, 플러그인별 동작, 월드, DB 스키마 등은 별도 인수인계 대상이다. 이 문서를 읽었다는 이유로 해당 시스템을 수정하거나 이전하지 않는다.

**이 문서가 준비되었다고 실행 환경 이전이 완료된 것은 아니다.** 현재 확인된 접속은 노트북에서 호스팅으로 연결한 SSH이고, dot의 클라우드에서 같은 호스팅으로 직접 연결하는 경로는 아직 검증하지 않았다.

## 사용자가 요청한 핵심 원칙

1. 채팅을 제외한 작업은 노트북의 CPU, 메모리, 디스크 처리와 인터넷 회선을 사용하지 않도록 한다.
2. dot의 클라우드 환경에서 작업을 계획하고 도구를 사용한다. SSH 연결을 시작하는 프로그램도 노트북이 아닌 dot의 클라우드에서 실행해야 한다.
3. 프로젝트 파일, 설치 파일, 의존성, 빌드 결과와 작업에 필요한 프로그램은 호스팅 컴퓨터에 둔다. 대용량 파일을 노트북으로 받아서 다시 호스팅에 올리지 않는다.
4. 코드 작성과 수정안 준비는 dot이 자기 클라우드에서 직접 수행한다. 기존 소스는 SSH로 호스팅에서 읽고 수정하며, 클라우드에서 만든 새 파일이나 수정안은 호스팅으로 직접 전송해 적용한다. 프로젝트의 최종 소스, 의존성 다운로드, 빌드, 테스트, 서버 실행과 DB 처리는 호스팅에 둔다. Codex에 개발을 맡기는 것은 기본 작업 경로에 포함하지 않는다.
5. 노트북은 사용자가 메시지를 보내고 결과를 확인하는 단말로 사용한다. 사용자가 별도로 요청한 런처 교체, 파일 수령이나 게임 플레이는 그 요청 범위에서만 예외로 다룬다.
6. 현재 대화나 과거의 로컬 작업을 dot에 연결했다고 해서 실행 환경이 자동으로 바뀌었다고 설명하지 않는다.
7. 클라우드에서 호스팅에 접속할 수 없으면 제약을 정확히 보고한다. 사용자 허락 없이 노트북의 터미널이나 SSH로 우회하지 않는다.

실행 환경 선택은 문구보다 실제 도구의 실행 위치로 확인한다. “클라우드에서 할게”라고 말하고 노트북의 SSH 명령을 실행하는 것은 이 요구를 충족하지 않는다.

## 목표 작업 경로

목표 경로는 다음과 같다.

```text
사용자 노트북
  └─ 메시지 전송과 결과 확인
       └─ dot의 클라우드 실행 환경
            └─ 클라우드에서 시작한 SSH 연결
                 └─ 호스팅의 일반 작업 계정
                      └─ 파일 설치와 수정, 다운로드, 빌드와 테스트
```

dot이 직접 코딩하고 SSH로 호스팅 작업을 수행하는 것이 기본 경로다. 사용자의 개발 요청, 서버 파일 수정 요청이나 SSH 접속 허가는 Codex 사용 허가가 아니다. Codex Cloud 작업 생성, 로컬 Codex 작업 생성, 기존 Codex 작업에 후속 지시 전송, 호스팅의 Codex CLI 실행과 자동 위임은 모두 사용자가 명시적으로 허가한 범위에서만 가능하다. 도구 부족, 작업 규모나 접속 실패를 이유로 자동 전환하지 않는다.

클라우드가 호스팅에 파일을 전송하거나 호스팅이 인터넷에서 파일을 내려받는 것은 노트북의 회선을 경유하지 않는 경로로 구성한다. SSH 출력, 진행 상황과 최종 결과는 작게 유지한다. 사용자의 노트북에서 채팅 앱을 표시하고 메시지를 주고받는 데 필요한 자원은 남는다.

## 용어와 환경을 구분하는 방법

| 구분 | 의미 | 이 작업에서의 용도 |
| --- | --- | --- |
| 사용자 노트북 | 현재 사용자가 메시지를 보내는 개인 PC | 채팅과 결과 확인 |
| dot 클라우드 컴퓨터 | dot이 사용하는 자체 클라우드 실행 환경 | dot의 직접 코딩, 지원되는 도구 실행, 호스팅 직접 접속 |
| Codex Cloud | dot과 별개의 클라우드 코딩 작업 환경 | 기본 사용 금지, 사용자의 명시적 허가가 있을 때만 검토 |
| 호스팅 컴퓨터 | SSH로 접속하는 Windows Server 2019 컴퓨터 | 프로젝트 파일 보관과 실제 개발 작업 실행 |
| 노트북에서 실행한 SSH | 노트북의 SSH 프로그램이 호스팅에 연결하는 방식 | 기존 방식이며 목표 경로가 아님 |
| 클라우드에서 실행한 SSH | 클라우드의 SSH 프로그램이 호스팅에 직접 연결하는 방식 | 직접 접속이 검증되면 사용할 목표 경로 |

dot 클라우드 컴퓨터, Codex Cloud와 사용자의 Windows 호스팅은 서로 다른 환경이다. 한 환경의 파일, SSH 별칭, 인증 정보, 브라우저 로그인과 프로그램이 다른 환경에 자동으로 생기는 것으로 가정하지 않는다.

사용자가 말한 “로컬 파일을 호스팅에 설치”는 파일을 호스팅의 작업 디렉터리에 실제로 배치하라는 뜻이다. dot 클라우드의 임시 폴더에만 저장하고 호스팅에 설치했다고 보고하면 안 된다.

Codex의 경로와 버전은 기존 설치 현황을 보존한 기록이다. 설치되어 있다는 이유로 사용하지 않는다. 사용자의 명시적 허가가 없는 동안에는 Codex CLI의 실행, 로그인 확인과 작업 연결 점검도 진행하지 않는다. PowerShell, Git, Java, 편집 도구와 프로젝트 빌드 도구로 호스팅 작업을 직접 수행하는 것은 Codex 위임에 해당하지 않는다.

Node.js가 PATH에서 발견되지 않았다는 결과를 노트북의 Node.js로 작업하라는 의미로 받아들이지 않는다. 필요하다면 호스팅에서 기존 설치를 확인하고, 필요한 경우 호스팅에 설치한다. 시스템 전체 설치가 필요한지, 작업 폴더 안에 설치할 수 있는지 판단한다.

호스팅 SSH의 기본 로그인 셸은 이전 구성에서 Git Bash로 설정했다. 기본 셸과 실제 사용할 PowerShell을 구분하고, Windows 전용 명령은 명시적으로 PowerShell로 호출한다.

## dot이 처음 수행할 확인

첫 작업은 프로젝트 기능 개발이 아니라 클라우드에서 호스팅으로 이어지는 경로 확인이다.

1. 이 문서를 읽고 노트북 자원 배제, dot 직접 개발, 호스팅 파일 설치와 Codex 무단 사용 금지를 자신의 작업 지침에 반영한다.
2. 현재 실행 환경의 종류, 도구 실행 위치, 컴퓨터 이름 또는 식별 정보를 확인한다. 클라우드 컴퓨터라는 UI 표시와 실제 실행기 정보를 함께 본다.
3. dot 클라우드에서 터미널 또는 명령 실행 도구를 사용할 수 있는지 확인한다. 제공되지 않는 도구를 있는 것처럼 가정하지 않는다.
4. 클라우드에 SSH 클라이언트와 필요한 파일 작업 도구가 있는지 확인한다.
5. 네트워크 정책상 호스팅의 22번 포트에 직접 연결할 수 있는지 확인한다.
6. 호스트 키와 클라우드 전용 인증을 준비한다.
7. 클라우드에서 일반 작업 계정으로 SSH 접속하고 호스팅 컴퓨터 이름, 사용자 이름과 작업 경로를 확인한다.
8. 승인된 호스팅 작업 폴더에 작은 확인 파일을 쓰고 다시 읽어 파일 작업 권한을 확인한다.
9. 실행 위치, 접속 결과와 남아 있는 제약을 짧게 보고한다.
10. 이 단계가 끝나기 전에는 클라우드 작업 경로가 완성되었다고 보고하지 않는다.

이 확인을 위해 노트북에서 터미널을 열거나, 노트북의 SSH 프로그램을 대신 실행하지 않는다. 사용할 수 없는 기능이 있으면 가능한 부분의 점검을 먼저 마치고 정확히 어떤 연결이나 권한이 필요한지 말한다.

## 클라우드 네트워크와 도구 제약

dot의 자체 클라우드 컴퓨터에서 소프트웨어 작업을 할 수 있다는 공식 설명은 있다. 하지만 이 사용자의 dot에 일반 터미널, SSH 클라이언트, 임의 TCP 연결이 실제로 제공되는지는 별도로 확인해야 한다.

Codex Cloud의 네트워크 설정과 dot의 클라우드 컴퓨터 설정을 섞어서 판단하지 않는다. 공식 Codex Cloud 안내에서 설명하는 VPN 경로는 HTTP와 HTTPS 중심이며 네이티브 SSH를 지원하는 경로로 안내되어 있지 않다. 따라서 “인터넷 허용”만 켜면 어느 환경에서나 SSH가 된다고 가정하지 않는다. [OpenAI 클라우드 환경 안내](https://learn.chatgpt.com/docs/environments/cloud-environments)

클라우드에서 SSH 직접 접속이 허용되지 않으면, 사용할 수 있는 승인된 작업 연결이나 호스팅 측 실행 방식을 먼저 조사한다. 이 문서는 새 공개 API, 공개 app-server, 우회 터널을 자동으로 설치하도록 승인하지 않는다.

연결할 방법이 확인되지 않으면 사용자에게 “클라우드에서 호스팅에 직접 접속하는 단계가 막혔다”라고 보고한다. 호스팅 작업을 계속하기 위해 노트북 SSH로 되돌아가는 것은 금지한다.

## 인증과 호스트 키

기존 호스팅 ED25519 호스트 키의 확인 기록은 다음과 같다.

```text
SHA256:0iuGhvx7qGqXlCkCBKr6ed3v4iLg7yJCnCVZcNkl+qM
```

dot 클라우드가 처음 접속할 때 제시되는 ED25519 키 지문을 이 값과 대조한다. 다른 키 종류의 지문과 비교해 불일치로 오판하지 않는다. 값이 다르면 호스팅 재설치나 키 교체가 실제로 있었는지 확인하고, 확인 없이 새 키를 신뢰하지 않는다.

클라우드에 노트북의 개인 키가 자동으로 있는 것으로 가정하지 않는다. 노트북의 개인 키, SSH 설정 폴더 전체, Codex 로그인 파일을 문서나 채팅에 붙여넣도록 요구하지 않는다.

인증 준비는 클라우드 환경이 제공하는 안전한 비밀 저장소나 지원되는 인증 방식을 우선한다. 클라우드에서 별도 SSH 키를 생성할 수 있다면 전용 키를 사용하고, 공개 키만 호스팅의 일반 계정에 등록하는 방식을 검토한다. 새 접속 키 등록에 필요한 승인 범위를 확인하고, 필요한 경우 사용자에게 공개 키 등록 방법을 구체적으로 제공한다. 이미 승인된 동일 작업에 반복 확인을 요구하지 않는다. 호스팅의 일반 계정 공개 키 파일은 `C:\Users\chacademi-codex\.ssh\authorized_keys`이며, 파일 존재만 확인했고 내용은 읽거나 공유하지 않았다. 새 공개 키를 추가할 때 기존 키와 접근 권한을 보존하고 파일을 통째로 덮어쓰지 않는다. 이 문서 작성 과정에서는 dot용 접속 키를 생성하거나 등록하지 않았다.

`StrictHostKeyChecking=no` 또는 `UserKnownHostsFile=/dev/null`로 확인을 우회하지 않는다. 자동 로그인 실패를 관리자 비밀번호로 자동 재시도하지 않는다.

사용이 허가된 프로그램의 인증 상태는 해당 프로그램의 상태 명령으로 확인한다. Codex는 사용자의 명시적 허가가 있을 때만 점검한다. `auth.json`, 개인 키 또는 환경 변수 전체를 출력해서 인증을 점검하지 않는다.

## 클라우드 SSH 설정 예시

다음은 **dot 클라우드가 Linux 형태의 셸과 OpenSSH를 제공하는 경우**에 사용할 설정 예시다. 실제로 키와 호스트 키를 준비한 뒤에만 사용한다. 현재 설치되어 있다는 의미는 아니다.

```sshconfig
Host chacademi-host
    HostName 211.53.196.231
    Port 22
    User chacademi-codex
    IdentityFile ~/.ssh/chacademi_dot_ed25519
    IdentitiesOnly yes
    BatchMode yes
    StrictHostKeyChecking yes
    UserKnownHostsFile ~/.ssh/chacademi_dot_known_hosts
    ConnectTimeout 10
    ServerAliveInterval 30
    ServerAliveCountMax 3
```

이 예시는 클라우드의 전용 설정 파일에 둔다. 기존 클라우드 SSH 설정이나 다른 작업의 인증을 덮어쓰지 않는다. 전용 설정 파일 이름은 예를 들어 `~/.ssh/chacademi_dot_config`로 사용할 수 있다.

호스트 키 수집 도구를 사용하는 경우, 네트워크에서 받은 키는 확인 전 후보일 뿐이다. 후보 키의 ED25519 지문을 위의 검증 기록과 비교한 후에만 클라우드의 전용 known_hosts 파일에 등록한다.

키와 호스트 확인이 끝난 뒤, 다음과 같은 짧은 점검을 **클라우드 터미널에서** 실행할 수 있다.

```bash
ssh -F ~/.ssh/chacademi_dot_config chacademi-host 'powershell.exe -NoProfile -NonInteractive -Command "[Environment]::MachineName; [Environment]::UserName; Test-Path -LiteralPath C:/Chacademi"'
```

확인할 값은 `WIN-RJ6L8DCCIHR`, `chacademi-codex`, 작업 폴더 존재 여부 `True`다. 도구 실행 위치가 클라우드였는지도 별도로 기록한다. 원격의 이름만 맞아도 접속을 시작한 쪽이 노트북이면 요구를 충족하지 않는다.

## 호스팅 작업 폴더와 파일 설치

호스팅의 `C:\Chacademi` 아래에서 작업한다. 기존 폴더가 있으므로 비어 있다고 가정하거나 전체 내용을 덮어쓰지 않는다.

| 분류 | 호스팅 저장 위치 | 처리 원칙 |
| --- | --- | --- |
| 인수인계와 작업 지침 | C:\Chacademi\handoff | 버전과 기준일을 기록 |
| 기존 프로젝트 소스 | C:\Chacademi\build-workspace | 관련 파일만 수정 |
| 내려받은 설치 파일 | C:\Chacademi\downloads | 호스팅에서 직접 다운로드 |
| 개발 도구와 캐시 | C:\Chacademi\tools | 필요한 도구만 설치 |
| 빌드 결과와 패키지 | C:\Chacademi\artifacts | 호스팅에 보관 |
| 새 파일 임시 수신 | C:\Chacademi\incoming\dot | 필요할 때 생성, 설치 후 정리 |
| 작업 기록 | C:\Chacademi\handoff | 비밀값을 제거한 환경 확인과 변경 기록 |

표에서 임시 수신 폴더 등 일부 경로는 앞으로 사용할 제안이다. dot은 존재 여부와 권한을 확인하고 필요한 폴더만 만든다.

프로그램을 `Program Files`나 시스템 경로에 설치해야 한다는 이유만으로 관리자 계정으로 전환하지 않는다. 일반 계정이 수정할 수 있는 작업 폴더에 도구를 설치할 수 있는지 먼저 확인한다.

파일을 새로 설치할 때는 목적, 출처, 최종 저장 경로, 덮어쓰는 기존 파일, 검증 방법을 명확히 한다. 라이브러리 설치와 실행 프로세스의 재시작은 서로 다른 조치다.

## 파일을 가져오는 경로

파일 출처에 따라 처리한다.

**인터넷에서 받을 파일:** 호스팅에서 직접 내려받는다. 노트북에서 받아 재전송하지 않는다. 출처가 공식 배포처인지, 파일 버전과 체크섬이 확인되는지 점검한다. 필요하면 호스팅에 임시 파일로 저장하고 확인 후 최종 위치로 옮긴다.

**dot 클라우드에서 생성한 작은 파일:** 클라우드에서 호스팅으로 직접 전송한다. 소스 수정 파일, 설정이나 문서는 최소 파일만 전송하고 설치 위치를 확인한다. 클라우드 임시 파일만 저장하고 호스팅 작업을 끝냈다고 보고하지 않는다.

**호스팅에 이미 있는 파일:** 호스팅에서 찾아 읽고 관련 부분만 수정한다. 분석을 위해 프로젝트 전체를 클라우드로 복제하지 않는다. 결과 판단에 필요한 작은 출력만 반환한다.

**사용자가 노트북에만 가지고 있는 파일:** 해당 파일이 작업에 꼭 필요한지 먼저 확인한다. 필요하다면 사용자가 요청하거나 승인한 최소 파일의 최초 전달만 진행한다. 최초 업로드에는 노트북 회선이 사용된다는 사실을 정확히 설명한다. “노트북 파일을 한 번도 읽거나 보내지 않고 옮겼다”라고 보고하지 않는다.

이번 요청은 인수인계 문서 준비다. 기존 프로젝트 전체, 대용량 리소스, 월드, 백업이나 사용자 데이터 이전을 지금 실행하라는 요청이 아니다.

## 전송과 설치 검증 예시

다음 예시는 클라우드에서 직접 SSH 접속이 검증된 뒤 사용할 수 있다. `<...>` 형태의 값은 실제 파일과 경로로 바꿔야 한다. 예시를 그대로 실행하지 않는다.

호스팅의 승인된 임시 수신 폴더가 없다면 작은 폴더 하나만 만든다.

```bash
ssh -F ~/.ssh/chacademi_dot_config chacademi-host 'powershell.exe -NoProfile -NonInteractive -Command "New-Item -ItemType Directory -Path C:/Chacademi/incoming/dot -Force | Out-Null"'
```

작은 파일은 클라우드에서 호스팅으로 직접 보낸다.

```bash
scp -F ~/.ssh/chacademi_dot_config /cloud/path/example.ps1 chacademi-host:C:/Chacademi/incoming/dot/example.ps1
```

클라우드에서 원본 파일의 SHA256을 구하고, 호스팅에서 받은 파일의 SHA256을 확인해 두 값을 비교한다. 셸에 맞는 해시 도구를 사용한다. Windows의 예시는 다음과 같다.

```powershell
Get-FileHash -LiteralPath 'C:\Chacademi\incoming\dot\example.ps1' -Algorithm SHA256
```

최종 설치 위치로 이동하기 전에 기존 파일을 확인한다. 백업이 필요하면 해당 파일만 호스팅 안에 보관한다. 해시가 맞아도 기능이 적용되었다는 뜻은 아니다. 파일 설치, 빌드 성공, 프로세스 로드와 실제 동작 검증을 구분한다.

## 원격 명령을 작성하는 원칙

호스팅이 Windows라는 점을 기준으로 명령을 작성한다. dot 클라우드가 Linux여도 호스팅에서 실행되는 명령은 Windows와 해당 셸의 문법을 따라야 한다.

Windows 전용 작업에서는 명시적으로 PowerShell을 사용한다. PowerShell 7이 필요한 기능은 `C:\Program Files\PowerShell\7\pwsh.exe`로 호출한다. 기본 `powershell.exe`는 Windows PowerShell일 수 있다.

길거나 복잡한 명령을 여러 셸의 따옴표에 겹쳐 넣지 않는다. 작은 스크립트를 클라우드에서 만들고 호스팅으로 전송한 뒤 `-File`로 실행하는 방식을 우선한다. 명령 문자열에 비밀번호나 토큰을 넣지 않는다.

이전 Windows SSH 작업에서는 긴 인코딩 명령이 실행 계층의 길이 제한으로 잘릴 수 있었다. 긴 인수인계 본문이나 대형 스크립트를 EncodedCommand 한 줄에 넣어 전송하지 않는다. 필요한 경우 작은 명령에만 UTF16LE Base64 인코딩을 사용한다. 인코딩은 암호화가 아니므로 비밀정보를 숨기는 수단으로 사용하지 않는다.

환경 변수나 스크립트 변수에는 `task`, `dot` 등 작업 전용 이름을 사용한다. `HOME`, `CODEX_HOME` 같은 시스템 경로 변수를 다른 용도로 덮어쓰지 않는다.

삭제나 이동은 최종 절대 경로와 대상 파일을 먼저 확인한다. 서로 다른 셸에 경로 문자열을 넘기며 삭제 명령을 조합하지 않는다. Windows에서는 `-LiteralPath`로 실제 경로를 지정하고, 전체 작업 폴더 삭제나 정리 명령을 임의로 실행하지 않는다.

종료 코드와 짧은 오류 문구를 확인한다. 결과를 얻기 전에 “설치 성공”이라고 보고하지 않는다.

## dot 직접 개발과 Codex 사용 승인

**dot은 직접 개발하는 수행자이며, 이 프로젝트를 Codex에 자동으로 맡기는 조정자로 동작하지 않는다.** 자신의 클라우드에서 코드를 작성하고, SSH로 호스팅의 기존 소스와 설정을 읽고 수정한다. 새 파일은 클라우드에서 호스팅으로 직접 보내고 실제 빌드와 검증은 호스팅에서 수행한다. 사용자에게 일반적인 기능 제작이나 서버 수정 지시를 받았다는 사실만으로 Codex 사용 권한을 얻은 것으로 해석하지 않는다.

dot이 직접 수행하는 개발 작업의 계획과 기록에는 다음 정보가 들어가야 한다.

- 사용자가 원하는 결과와 현재 허용된 범위.
- 이 문서의 두 핵심 원칙인 노트북 자원 배제와 호스팅 파일 설치.
- 실제 실행 환경과 호스팅 접속이 검증되었는지 여부.
- 기본 작업 계정과 수정할 호스팅 경로.
- 이전 작업에서 확인된 사실, 이미 완료된 작업, 미확인 사항.
- 검증 기준과 결과를 보관할 호스팅 경로.
- 클라우드 접속이 막혔을 때 노트북으로 우회하지 말라는 지시.

직접 작업하는 데 필요한 정보만 확인하고, 작업 범위를 벗어난 기능은 임의로 수정하지 않는다. 소스와 설정의 최종 기준은 호스팅 파일이다. 클라우드에서 작성한 수정안도 호스팅에 적용하고 결과를 검증해야 완료로 보고한다.

제품이 Codex 위임 기능을 제공하더라도 이 프로젝트에서의 사용 허가는 별개다. Codex의 신규 작업 생성, 기존 작업 재개와 후속 지시, 로컬 또는 클라우드 작업 실행과 SSH를 통한 호스팅 Codex CLI 실행은 모두 사용자의 명시적 허가가 필요하다. 허가는 사용자가 승인한 작업과 범위에만 적용하며 다른 작업으로 확대하지 않는다. [OpenAI dot 작업과 메모리 안내](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

dot의 클라우드 도구만으로 직접 코딩하거나 SSH로 접속할 수 없으면 그 제약을 보고한다. Codex를 몰래 실행해 해결하거나 노트북 작업으로 우회하지 않는다. 별도 Codex 사용이 꼭 필요하다고 판단하면 이유와 대상 작업, 실행 환경을 구체적으로 제시하고 명시적 허가를 받은 뒤에만 진행한다. 이미 승인된 동일 범위는 반복해서 묻지 않는다.

## 일반 작업과 권한 변경

기본 계정은 `chacademi-codex`다. 이 계정은 일반 작업 계정이며 관리자 계정으로 일상적인 개발을 수행하지 않는다.

사용자가 요청한 범위 안의 읽기, 분석, 소스 수정, 빌드와 검증은 진행한다. 이미 승인된 작업을 다시 승인받느라 반복해서 멈추지 않는다. 반대로 과거에 승인한 특정 시스템 변경을 새 작업에 대한 포괄적인 관리자 권한으로 해석하지 않는다.

새 계정 생성, 접속 키 권한의 변경, 방화벽·서비스·예약 작업 권한 변경, 새로운 외부 공개 엔드포인트 구성처럼 시스템 접근 범위가 바뀌는 작업은 현재 요청의 승인 범위를 확인한다.

승인이 필요한 경우는 무엇을 바꿀지, 왜 필요한지, 대상 계정과 경로, 예상 영향과 복구 방법을 구체적으로 제시한다. 가능하면 승인 전에 검토 가능한 파일이나 변경 내용을 준비한다.

도구의 자동 승인 검토가 거부했다면 거부한 작업과 제시된 이유를 사용자에게 정확히 설명한다. 같은 작업을 다른 명령으로 숨겨 재시도하거나 검토를 우회하지 않는다.

이 문서 작성은 dot의 접속 키 추가, 관리자 권한 부여, 포트 공개 또는 새 서비스 설치를 수행한 것이 아니다.

## 노트북 사용 금지와 허용된 예외

dot과 사용자가 명시적으로 허가한 예외 작업의 수행자는 다음 작업을 노트북에서 실행하지 않는다.

- SSH나 SCP를 통해 호스팅에 작업 명령과 파일을 전달하는 실행기.
- 소스 분석을 위한 전체 프로젝트 복사와 대형 검색 작업.
- Gradle, Maven, npm, pip 등 빌드와 의존성 설치 작업.
- 테스트 서버, 게임 서버, DB 또는 대용량 리소스 처리.
- 대형 로그, 백업, 모델, 설치 파일과 결과물의 자동 다운로드.
- 클라우드 접속 실패를 이유로 노트북의 터미널·브라우저·개인 파일에 접근하는 우회.

사용자가 명시적으로 요청한 채팅 첨부, 최종 파일 수령, 런처 교체 또는 게임 플레이는 그 요청 범위의 예외다. 예외를 수행한 경우 어디에서 어떤 파일이나 통신을 처리했는지 정확히 알린다.

사용자가 노트북을 dot의 “내 컴퓨터”로 연결하면, dot이 만든 로컬 작업이 노트북에서 실행될 수 있다. 이 프로젝트의 기본 실행 대상으로 노트북을 선택하지 않는다. 필요하다면 사용자가 프로젝트 작업에 대한 노트북 접근을 허용하지 않도록 설정을 검토할 수 있다. 다른 프로젝트의 연결이나 권한을 임의로 해제하지 않는다.

작업 지침을 저장하는 것과 실제 환경을 바꾸는 것은 다르다. 파일이나 메모리에 “클라우드 우선”을 기록해 놓고 로컬 도구를 사용하면 요구를 충족하지 않는다.

## 자원 사용과 결과 전달

크고 반복적인 처리는 호스팅의 기존 파일을 기준으로 수행한다. dot은 필요한 짧은 결과만 받아 다음 결정을 내린다.

- 전체 로그 대신 관련 오류와 필요한 전후 문맥만 가져온다.
- 전체 폴더 목록 대신 대상 경로, 파일명, 크기와 확인한 해시 등 필요한 요약만 반환한다.
- 외부 파일 다운로드와 압축 해제는 호스팅에서 처리한다.
- 빌드 캐시는 호스팅에 유지하고 매번 새로 내려받지 않는다.
- 실행 중인 장기 작업은 중복으로 시작하지 않는다. 상태를 확인하고 필요한 시점에만 조회한다.
- 작업 상태가 바뀌지 않을 때 짧은 간격으로 큰 출력을 반복 조회하지 않는다.
- 결과물은 기본적으로 호스팅에 보관한다. 사용자가 파일을 받고 싶다고 한 경우 해당 결과물만 제공한다.
- 리소스 한도가 필요하면 호스팅의 현재 여유 메모리와 실행 중인 프로세스를 확인해 작업 범위에 맞게 정한다. 검증 없이 무제한 병렬 빌드를 시작하지 않는다.

원격 실행을 했다는 사실만으로 노트북 네트워크 사용량이 0이라고 보고하지 않는다. 클라우드에서 연결을 시작했는지, 노트북으로 실제 파일을 전송했는지 구분해서 설명한다.

## 작업 기록과 상태 보고

dot은 호스팅에서 확인한 정보를 작은 작업 기록으로 남길 수 있다. 다음은 기록할 항목의 예시이며 실제 값으로 작성한다.

```json
{
  "checked_at": "<Asia/Seoul 기준 날짜와 시간>",
  "controller_environment": "<dot의 실제 클라우드 실행 환경>",
  "connection_origin": "<cloud 또는 확인된 실제 위치>",
  "transport": "<검증된 연결 방식>",
  "target_host": "211.53.196.231",
  "target_port": 22,
  "target_computer": "WIN-RJ6L8DCCIHR",
  "target_account": "chacademi-codex",
  "working_directory": "C:\\Chacademi",
  "host_key_verified": false,
  "authentication_verified": false,
  "write_read_verified": false,
  "codex_use_authorized": false,
  "codex_work_started": false,
  "laptop_execution_used": false,
  "laptop_file_transfer_used": false,
  "blockers": []
}
```

예시의 `false`는 기본값이다. 실제 확인 없이 `true`로 바꾸지 않는다. 이 파일에는 개인 키, 토큰, 비밀번호 또는 전체 환경 변수 목록을 넣지 않는다.

사용자에게는 수행한 일, 어디서 수행했는지, 확인한 결과, 아직 남은 부분을 짧게 알려준다. 서버 기능 설명이나 긴 로그를 매번 반복하지 않는다.

구체적인 구분 예시는 다음과 같다.

- 문서 작성 완료와 클라우드 SSH 접속 완료.
- 파일 준비 완료와 호스팅 파일 설치 완료.
- 빌드 성공과 실제 실행 프로세스에 적용 완료.
- 환경 점검 성공과 실제 프로젝트 기능 검증 완료.

## 접속이 막혔을 때의 대응

| 막힌 지점 | dot이 확인할 내용 | 다음 대응 |
| --- | --- | --- |
| 클라우드 명령 실행 도구 없음 | dot 본인에게 실제 제공된 도구 | 도구 부재를 보고하고 허가 없이 Codex로 위임하지 않음 |
| SSH 클라이언트 없음 | 클라우드에서 설치 가능한지와 권한 | 해당 클라우드에만 설치를 검토 |
| 22번 포트 연결 불가 | 목적지, 포트, 네트워크 정책 | 인증 문제로 단정하지 말고 연결 제한을 구분 |

| 공개 키 인증 실패 | 사용자 이름, 키 등록, 계정 권한 | 관리자 계정이나 비밀번호로 자동 우회하지 않음 |
| 작업 폴더 쓰기 실패 | 최종 경로와 해당 계정의 권한 | 필요한 경로만 확인하고 권한 변경 범위를 제시 |
| dot의 직접 개발 도구로 진행 불가 | 부족한 도구와 필요한 작업 범위 | 제약을 보고하고 Codex 사용이 필요하면 명시적 허가를 먼저 받음 |
| 작업 실행 위치가 노트북임 | 실제 실행기와 접속 시작 위치 | 해당 경로를 중단하고 dot 클라우드에서 수행할 방법을 확인 |

막혔을 때 사용자에게는 “무엇을 어느 환경에서 확인했고, 어떤 부분 때문에 진행할 수 없으며, 다음에 무엇이 필요한지”를 말한다. 지원되지 않는 부분을 추측으로 채우지 않는다.

노트북에서 대신 처리하면 문제가 해결될 것 같아도 사용자의 핵심 요구를 어기는 우회다. 연결이 막히면 문서 정리나 이미 확보된 정보 분석 등 클라우드에서 가능한 일을 진행하고, 접속이 필요한 작업은 미완료로 남긴다.

## 환경 인수 완료 기준

다음 항목이 충족되어야 dot이 작업 환경을 인수했다고 보고할 수 있다.

- [ ] dot이 노트북 자원 사용을 피해야 한다는 목적을 이해했다.
- [ ] dot 본인의 실제 명령 실행 환경이 클라우드임을 확인했다.
- [ ] 호스팅 접속을 시작하는 쪽이 노트북이 아닌 클라우드임을 확인했다.
- [ ] 클라우드에서 호스팅 SSH 22번 포트로 직접 연결했다.
- [ ] ED25519 호스트 키 지문을 확인했다.
- [ ] 일반 계정 chacademi-codex로 인증했다.
- [ ] 호스팅 컴퓨터 이름과 C:\Chacademi 작업 경로를 확인했다.
- [ ] 승인된 작업 폴더에서 작은 파일을 쓰고 다시 읽었다.
- [ ] 호스팅의 작업 지침을 읽었다.
- [ ] dot이 직접 코드를 작성하고 SSH로 호스팅 파일을 수정할 도구를 확인했다.
- [ ] 파일 설치와 결과 보관을 호스팅에서 수행할 수 있다.
- [ ] 명시적 허가 없이 Codex 작업을 생성하거나 실행하거나 지시하지 않는 원칙을 확인했다.
- [ ] 노트북의 SSH·빌드·다운로드를 사용하지 않는 경로를 확인했다.
- [ ] 미완료인 항목과 실제 검증 범위를 사용자에게 보고했다.

인수인계 문서 작성 시점에는 위 체크리스트를 완료 처리하지 않는다. 현재 확인된 노트북 SSH 접속을 클라우드 접속의 증거로 사용하지 않는다.

## dot에게 바로 전달할 지시문

아래 지시문과 이 문서를 함께 dot에게 전달하면 된다.

```text
이 문서를 읽고 내 작업 환경을 인수해줘.

나는 일본에서 노트북을 사용하고 있고, 작업 때문에 노트북의 네트워크와 메모리를 사용하는 것을 피하고 싶어.

채팅을 제외한 작업은 네 클라우드 환경에서 처리해. 너 자신이 클라우드에서 직접 코드를 작성하고, 그 클라우드에서 시작한 SSH로 호스팅의 소스와 서버 설정을 읽고 수정해. 새 파일이나 수정안은 클라우드에서 호스팅으로 직접 전송하고, 최종 소스와 설치 파일, 의존성, 빌드와 테스트는 호스팅 컴퓨터에 둬.

지금은 서버 기능 개발이나 기존 프로젝트 전체 이전을 시작하지 마. 먼저 네 클라우드에서 호스팅에 직접 접속할 수 있는지, 파일을 설치하고 원격 명령을 실행할 수 있는지 확인해.

네 클라우드에서 SSH를 사용할 수 없거나 인증이 준비되지 않았다면 노트북의 로컬 도구로 우회하지 마. 가능한 부분을 확인한 뒤 정확히 무엇이 필요한지 알려줘.

내가 명시적으로 허가하기 전에는 Codex 작업을 만들거나 기존 Codex 작업에 지시하거나 재개하지 마. Codex Cloud, 로컬 Codex, 호스팅 Codex CLI 실행과 자동 위임 모두 해당해. 일반적인 개발 요청이나 SSH 작업 허가는 Codex 사용 허가가 아니야. 네 도구로 할 수 없는 작업은 제약을 알려주고, 필요하면 Codex 사용 이유와 범위를 제시해서 허가부터 받아.

이 문서를 읽었다는 것과 실행 환경 연결이 완료되었다는 것을 구분해서 보고해줘. 실제 접속 경로와 계정, 검증 결과와 남은 제약을 짧게 알려줘.
```

## 다음 단계와 이번 문서의 범위

dot의 첫 단계는 환경 이해와 직접 접속 검증이다. 이후 사용자가 요청하면 기존 파일의 최소 이전과 프로젝트별 작업 인수인계를 진행한다. 서버 시스템과 현재 호스팅 운영 상태는 [차카데미 서버 시스템과 호스팅 운영 인수인계](https://chatgpt.com/space/page_994adbd00b7081918eb21c320da491c2)에 따로 정리했으며, 호스팅 파일은 `C:\Chacademi\handoff\SERVER_HANDOFF.md`다. 서버 작업을 이어갈 때 두 문서를 함께 읽는다.

이번 문서 작성에서는 다음을 수행하지 않았다.

- dot의 개인 키 생성이나 호스팅 공개 키 등록.
- dot 클라우드에서 호스팅으로 직접 SSH 접속.
- 새 Codex Cloud 환경 생성이나 게시.
- dot의 컴퓨터 접근 설정 변경.
- 호스팅 관리자 권한 부여나 포트 변경.
- 기존 프로젝트 전체 또는 대용량 파일 이전.
- 서버 기능, 플러그인, DB나 게임 데이터 수정.

노트북과 호스팅에 있는 기존 AGENTS.md는 호스팅 우선 작업 원칙을 담고 있다. dot의 목표는 그 원칙에 더해 제어용 SSH 실행기까지 클라우드로 옮기는 것이다. 지침 저장만으로 현재 노트북 대화의 실행 환경이 바뀌었다고 주장하지 않는다.

이 문서 자체는 사용자가 요청한 작은 인수인계 전달 파일이다. 현재 대화에서 문서를 만들고 호스팅에 복사하는 작업은 클라우드 접속 이전 완료의 증거가 아니다.

## 공식 안내와 정보의 출처

사용자 요청과 이 대화에서 확인한 호스팅 정보가 환경 인수인계의 기준이다. OpenAI 제품의 지원 범위는 다음 공식 안내를 참고한다.

- [dot 컴퓨터와 앱 연결](https://learn.chatgpt.com/docs/dots/computers-and-apps): dot의 자체 클라우드 컴퓨터와 연결된 개인 컴퓨터는 별개의 환경이다. 자신의 컴퓨터를 dot에 연결하는 권한은 기존 Codex 연결과도 별개다.
- [dot 작업과 메모리](https://learn.chatgpt.com/docs/dots/tasks-and-memory): 제품의 작업 관리와 Codex 위임 기능 설명이다. 이 프로젝트는 dot의 직접 개발이 기본이며, 제품에 기능이 있다는 사실은 Codex 사용 허가가 아니다. Codex Cloud를 사용하도록 별도 승인받은 경우에만 관련 환경 준비와 연결을 검토한다.
- [Codex 클라우드 환경](https://learn.chatgpt.com/docs/environments/cloud-environments): 클라우드 작업 환경과 네트워크·인증 접근을 별도로 준비하고 검증한다.
- [원격 연결](https://learn.chatgpt.com/docs/remote-connections): 원격 호스트 연결과 클라우드 작업의 지원 범위는 다르며, 현재 대화를 클라우드로 자동 이동할 수 있다고 가정하지 않는다.

제품 기능과 제공 도구는 변경될 수 있다. dot은 자신의 현재 도구와 권한을 확인하고, 문서 설명만으로 실제 접속 성공을 보장하지 않는다. 이 인수인계는 특정 모델의 무제한 사용, 별도 비용 면제 또는 계정 기능 제공을 주장하지 않는다.
