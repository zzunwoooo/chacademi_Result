## 0-1. 2차 수정 (오너 피드백 2026-10-17)

- **보유 골드 칸**: balance_field 양끝 다이아몬드 장식(원본 약 70px = 화면 14px) 안쪽으로 동전·글자·금액을 넣음. 검색 아이콘·글자도 안쪽으로.
- **가격 열**: `구매가`/`판매가` 글자와 동전은 **고정 열에 좌정렬**, 금액은 구매 버튼 앞에 **우정렬**(`AMOUNT_RIGHT`). 긴 금액은 자르지 않고 줄어듦. 판매 행의 `보유 N개`도 우정렬.
- **수량 직접 입력**: 숫자 칸 클릭 → 포커스 + 전체 선택(바로 입력하면 덮어씀, 선택 표시 있음), 마우스 올리면/포커스면 칸 강조. 다른 곳 클릭·Enter·ESC 로 빠질 때 빈 값/0 → 1, 최대 초과 → 최대로 보정. −/+ 버튼은 칸 장식 안쪽으로 옮김.
- **알림**: 목록 아래 끝에서 90px 위로.
- **배경 블러**: `render` 시작에서 바닐라 `renderBackground`(월드 블러 + 옅은 메뉴 어둡게) 호출. 블러 세기는 플레이어 옵션 「메뉴 배경 흐림」을 따른다(0이면 블러 없음).

## 2. 화면 구성

- 화면 맞춤: `min(width*0.98/1672, height*0.98/941)` 균일 배율, 그리기·마우스 판정 모두 `SocialLayout.Fit` 같은 역변환.
- **shop_frame**: 가로는 한 배율(0.794). 세로는 장식이 있는 위(원본 0~300px)·아래(1000~1118px)를 같은 배율로 고정하고, 장식 없는 가운데 띠만 늘린다(≈1.05배). 원본 PNG 의 머리 부분이 시안보다 높아서, 보유 골드·검색·탭 줄은 시안보다 약 25px 아래(프레임 안쪽 패널 안)에 있다. 행은 시안 128 대신 **124px**, 간격 8 (4줄 고정).
- 나머지 패널·버튼: **높이에 맞춘 균일 배율 + 가로 3-slice**(세로 비율 불변). 끝 장식 폭(원본 px)은 manifest 의 48 이 실제 장식보다 작아서 PNG 를 보고 정했다: item_row 90, item_slot 130, gold_button 180, navy_button 130, footer 70, balance 80, search 90, tab 21~22.
- 상태 이미지: item_row 기본/hover/selected, gold·navy 기본/hover/pressed/disabled, tab idle/selected × 상태, close 기본/hover/pressed. pressed 는 화면이 받은 마우스 누름~뗌으로 판단.
- 스크롤바: scrollbar.png 를 위캡 0~4 / 트랙 132~488 / 아래캡 488~512 / 손잡이 4~132(위·가운데·아래 3조각)로 나눠 그린다. 휠, 트랙 클릭, 손잡이 드래그 지원.
- 글꼴: 제목·상품명·NPC 이름·구매하기 = 마루부리(`section`), 본문 로어 = Pretendard regular(`body`), 라벨 = Pretendard medium(`label`), 숫자·버튼 = Pretendard bold(`hud_bold`). 긴 글은 82% 까지 줄인 뒤 말줄임(…). **숫자(가격·골드·합계)는 자르지 않고** 45% 까지 줄이며, 행 가격은 필요하면 최대 110px 왼쪽으로 옮긴다.
- 금액은 표시할 때만 `1,200` 처럼 쉼표를 넣는다. 요청·계산에는 서버 원래 문자열을 쓴다.

## 3. NPC·이름표

- 왼쪽 일러스트는 기존과 같이 상점 설정의 `portrait` → `magiccodex:textures/gui/dialogue/<portrait>.png`. 크기는 PNG 헤더에서 읽어 비율 유지(최대 높이 1000, 최대 폭 640).
- **일러스트 아래 끝을 실제 화면 아래(또는 그 아래)에 맞춘다** → 원본의 잘린 아래 가장자리가 화면 안에 보이지 않는다. 이름표가 허리를 가린다. 4:3·5:4 처럼 위아래 여백이 생기는 화면에서도 아래 끝은 화면 끝에 붙는다.
- 이미지가 없거나 이름이 잘못되면 일러스트를 그리지 않고 이름표만 그린다(오류 없음).
- 이름표 nameplate.png 는 균일 배율(0.247). 위: 역할(라벨 18px, 별 끝과 가운데 선 사이), 아래: NPC 실제 이름(마루부리 38px). 긴 이름은 줄이고 말줄임.
- **역할 문구는 "상점 주인" 고정.** 프로토콜에 역할 값이 없어서다(시안의 "잡화점 주인"처럼 상점마다 바꾸려면 Response 에 필드를 추가해야 함 → 통신 변경이라 하지 않음).
- 에드윈 일러스트는 등록하지 않았다.

## 4. 동작

- **탭**: 전체 = 구매나 판매 가격이 있는 상품, 구매 = 구매가 있는 것, 판매 = 판매가 있는 것. 상점에 해당 상품이 하나도 없으면 그 탭은 disabled.
- **전체 탭에서 구매·판매가 둘 다 되는 상품**: 「구매가 ○ 금색 구매」 / 「판매가 ○ 남색 판매」 두 줄. 한쪽만 되는 상품은 버튼 하나(구매=금색, 전체 탭의 판매 전용=남색, 판매 탭=금색). 판매 행에는 `보유 N개`.
- **행 버튼 = 선택**: 처음 누르면 그 상품과 방향(구매/판매)을 고르고 수량을 1로. 이미 고른 상품의 같은 버튼을 다시 누르면 `trade()` 로 거래. 하단 「구매하기/판매하기」도 같은 `trade()`. `trade()` 는 `busy` 이면 무시하고, 요청마다 새 operation UUID 하나 → 기존 `ShopClient.request`(대기 중이면 거부)·`ShopFeedback`(완료 operation 한 번만 소리) 그대로라 연타해도 한 번만 나간다.
- 구매불가(골드 부족)·판매불가(보유 0)·처리 중이면 해당 버튼 disabled(누르면 선택만).
- **수량**: −/+/직접 입력(숫자만, 9자리). 최대 = 기존 계산(스택×9, 576 이하, 골드/보유량). 하단에 `최대 N` 표시. 최대 초과는 버튼 disabled + 거래 시 기존 안내문.
- **검색**: 기존처럼 450ms 뒤 반영, 비었거나 결과 0이면 서버에 OPEN 재요청. 검색·탭·데이터가 바뀌면 `normalize()`: 스크롤 0, 선택이 안 보이면 첫 상품, 선택/방향이 바뀌면 수량 1, 스크롤 범위 보정.
- **빈 목록 문구**: 불러오는 중 / 판매 중인 상품이 없습니다 / 검색 결과가 없습니다 / 구매(판매)할 수 있는 상품이 없습니다.
- **키보드**: 입력칸에 포커스가 있으면 모든 키를 입력칸이 먹는다(단축키 오발동 방지). ESC·Enter 는 포커스만 풀고, 포커스가 없을 때 ESC 는 창 닫기(CLOSE 전송 유지).
- **아이콘**: 서버가 보내는 원본 ItemStack(NBT) 그대로 `drawItem` 96px. 리소스팩 고해상도 아이콘은 기존 `ItemIconTextures`(mixin)가 부드럽게 그리고, 없으면 그 아이템의 기본 모델 아이콘. 어두운 덮개 없음. 아이콘에 마우스를 올리면 기존 MagicCodex 아이템 툴팁.
- **설명**: 그 아이템의 로어. 툴팁과 같은 규칙으로 로어가 2줄 이상이면 첫 줄(아이템 종류)은 빼고 다음 2줄. 리소스팩 글리프(사용자 정의 영역 문자)는 지운다. 로어가 없으면 이름만 세로 가운데.
- 알림(서버 메시지)은 목록 아래쪽에 5초(마지막 0.5초 페이드), 아이템보다 위 레이어.
