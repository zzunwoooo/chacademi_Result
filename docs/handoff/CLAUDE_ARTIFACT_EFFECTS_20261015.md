## 0-1. 스쿨·야생 공유 (DB, 10-15 추가·점검)

오너: "장착 상태, 그로 인해 늘어난 능력치, 쿨타임 다 공유되어야 한다." 아티팩트 상태를 기존 공유 플레이어 상태 행(`PlayerStateStore`, MariaDB `codex_player_state`)에 넣었습니다.

- 마나·장신구와 같은 임대(lease)를 씁니다. 서버를 옮기면 이전 서버가 저장·해제한 뒤에 다음 서버가 불러옵니다.
- 저장 주기도 같습니다: 바뀐 사람은 5초마다, 전원은 30초마다, 나갈 때는 항상.

| 열 (새로 추가) | 내용 | 저장 시점 |
|---|---|---|
| `artifact_equipped` VARCHAR(512) | 장착 목록 | 장착/해제 즉시 |
| `artifact_cooldowns` TEXT | 사용 키 대기 시간 `id=끝나는시각ms;` | 사용 후 5초 안 |
| `artifact_runtime` TEXT | 내부 대기 시간·시간제 버프·켜 둔 상태(아래) | 주기·나갈 때 |
| `health` DOUBLE | 현재 체력 (모든 능력치 공통, `PlayerStats`) | 주기·나갈 때 |
| `artifact_biomes` TEXT | 여행자의 수첩 방문 바이옴 | 새 바이옴 후 5초 안 |
| `artifact_kept` BLOB | 튼튼한 끈이 지키는 아이템 | 쓰러질 때·돌려줄 때 즉시 |

`artifact_runtime`에 들어가는 것:

- **내부 대기 시간:** 비상 약초 120초, 연막 단추 60초, 역전의 메달 60초, 마나 방울 귀걸이 60초
- **시간제 버프 (남은 시간 그대로):** 전쟁 북·뿔피리, 음유시인, 수집 노트, 응원 확성기, 행운의 주사위, 사탕, 불씨 주머니, 비상 약초 등
- **진행 중인 효과·누적 값:** 역전의 메달, 마나 방울 발동 중, 주문 촛대·응원 깃발 준비 상태, 음표 수, 마나 순환 누적량, 경험치 소수점

### 능력치 통합 갱신: `PlayerStats` (오너 제안, 10-15)

서버를 옮길 때(또는 재접속할 때) 능력치를 다시 확인하는 로직을 **한 곳**으로 모았습니다. 앞으로 능력치가 붙는 기능은 여기에 등록만 하면 됩니다.

- **등록:**
  - `PlayerStats.register(이름, player -> …)`: 능력치 계산원입니다. 키가 고정된 모디파이어를 다시 거는 함수입니다. 지금 등록된 것은 `equipment`(장신구·지팡이), `artifacts`입니다.
  - `afterArrival(이름, …)`: 도착 후에 할 일입니다. 지금 등록된 것은 `artifacts`(끈 아이템 반환), `artifact-client`(도감·X키 HUD 재전송)입니다.
  - 공개 API: `MagicCodexBridge.stats()`, `refreshStats(player)`. 다른 플러그인도 쓸 수 있습니다.
- **도착 순서** (`PlayerStateBridge`가 공유 상태를 적용하고 ready 표시한 직후 `arrived` 호출):
  1. 등록된 계산원을 순서대로 실행합니다.
  2. 저장된 **현재 마나**를 되돌립니다. 새 최대치를 넘지 않습니다.
  3. 저장된 **현재 체력**을 되돌립니다(새 열 `health`). 새 최대치를 넘지 않고, 불러오는 동안 다쳤으면 되돌리지 않습니다.
  4. 도착 후 할 일을 실행합니다.
- **왜 필요했나:** 보너스는 숫자로 저장하지 않고 서버마다 다시 만듭니다. 그런데 다시 만들기 전에 게임과 `ManaAccount`가 현재 체력·마나를 기본 최대치로 깎고 있었습니다. 장신구에도 원래 있던 문제이고, 이번에 함께 고쳐집니다.
- **기존 처리를 대체:** 아티팩트 전용으로 넣었던 체력 복원(runtime `hp`)과 마나 복원은 지우고 `PlayerStats`로 옮겼습니다.
- **기후(`ClimateService`)는 등록하지 않았습니다.** 최대치를 바꾸지 않고(이동 속도·회복 배수), 원래 주기적으로 다시 계산되기 때문입니다.
- **장착/해제:** `artifactsChanged`가 아티팩트를 바로 다시 계산하고 공유 상태를 즉시 저장합니다.

### 그 밖

- **테이블:** 시작할 때 `ALTER TABLE … ADD COLUMN IF NOT EXISTS`로 열이 자동으로 붙습니다. MariaDB 10.0.2 이상이면 다시 실행해도 안전합니다. 기존 행은 빈 값입니다.
  - 참고용 `reference/output/mariadb-migration/schema.sql`에도 열 6개를 반영했습니다.
- **`artifacts.yml`:** 두 서버에 같은 파일을 두어야 합니다. 저장된 장착 목록은 그대로 남지만, 카탈로그에 없는 아이디는 효과·표시에서 빠집니다.
- **MariaDB를 쓰지 않는 서버**(SQLite 설정)는 예전처럼 PDC에만 남습니다.
- **확인한 것:**
  - `PlayerStateStore`·`PlayerStateBridge`·아티팩트 파일 모두 Paper API 소스로 javac 확인했습니다.
  - 상태 레코드 간이 검사(기존 8인자 생성자 호환, 길이 제한)를 통과했습니다.
  - **실제 MariaDB와 서버 이동은 확인하지 못했습니다.** GPT 확인 목록:
    1. 스쿨에서 거인의 심장 장착 → 야생 이동 → 최대 체력·현재 체력 유지
    2. 소원 동전 사용 → 이동 → 대기 시간이 이어짐
    3. 마나 목걸이로 마나가 기본 최대치를 넘은 상태 → 이동 → 마나 유지

### 스탯이 붙는 방식

- **바닐라 속성 모디파이어**(키 `magiccodexbridge:artifact_*`, 일시 적용): 최대 체력(고정/%), 이동 속도(%), 넉백 저항, 점프, 오를 수 있는 턱 높이.
- **ManaService 모디파이어**(키 `artifact:effect`): 최대 마나, 회복 배수, 스킬 가속.
- 값은 매번 다시 계산하고 같은 키에 덮어써서, 쌓이지 않습니다. 해제하면 0으로 돌아갑니다.
- 시간제 버프(신속·가속 등)는 출처마다 하나씩 두고, 다시 받으면 새로 갱신됩니다.

## 4. 확인 부탁

1. **빌드:** 세 모듈 모두 빌드해 주세요(`chacademi-party-velocity`, `magic-codex-paper`, `magic-mythic-paper`). 테스트는 기존 + 새 3개 파일입니다.
2. **로그:** 서버 시작 시 `아티팩트 마법 효과 연결: ChAcademiaMagicMythic`가 떠야 합니다. MagicMythic가 MagicCodexBridge보다 늦게 켜지므로, 켜질 때 연결합니다.
3. **실게임 확인 목록**
   - 장착/해제 즉시 스탯이 바뀌고, 해제 후 원래대로 돌아오는지
     - 예: 조끼 체력 +2, 거인의 심장 +30%
   - 파티를 만든 뒤 5초 안에 파티 판정이 바뀌는지
     - 예: 은둔자의 랜턴, 전술 지도, 신호 호루라기
   - 마법 피해 배율 확인
     - 예: 원소 반지
     - 같은 마법을 반지 끼고/빼고 비교해 주세요
   - 원소 반응 효과
     - 예: 원소 분필, 연쇄 장갑
   - 사용 키 효과
     - 예: 되감기, 원소 잉크병, 기폭 장갑
   - 대기 시간은 실패하면 시작되지 않습니다
4. **주의**
   - 시간 저당 증서, 유리 심장, 거인의 심장은 최대 체력 %를 바꿉니다. 다른 플러그인의 체력 표시가 있다면 같이 확인해 주세요.
   - 한가한 시계는 다른 모든 가속을 상쇄하는 방식입니다(음수 모디파이어).
   - 상태(대기·쌓인 음표 등)는 서버 메모리에만 있고, 서버를 옮기면 초기화됩니다.
     - 튼튼한 끈이 지켜 둔 아이템과 여행 기록은 PDC에 저장되어 남습니다.
5. **마법 쪽 파티 판정:** MagicMythic의 `alliesNear`는 지금도 "주변 모든 플레이어"를 아군으로 봅니다. 파티로 바꾸려면 `PartyRoster` 서비스를 쓰면 됩니다. 이번에는 바꾸지 않았습니다(동작 변경이라 오너 결정 필요).
