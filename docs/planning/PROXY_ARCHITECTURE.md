# 차카데미 프록시 및 서버 분리 기획

상태: 사용자 확정 구성 및 2026-10-26 배포 기록 기준. 실시간 가동 상태 보고서가 아니며, 미검증 항목은 완료로 간주하지 않는다.

## 접속 구조

단일 Velocity가 두 호스팅의 5개 백엔드로 연결한다. 별도의 신규 호스팅 프록시는 만들지 않는다. 이용자 접속점은 기존 호스팅의 25565 포트이며 백엔드 직접 접속은 정상 이용 경로가 아니다. Modern Forwarding을 사용한다. forwarding secret과 인증 정보는 저장소에 넣지 않는다.

## 자원 배치

| 호스트 | 역할 | 서버 ID | 최대 Java 힙 | 포트 |
|---|---|---|---|---|
| 기존: 32GB / i7-12700K / 8코어 | 프록시 | Velocity | 1GB | 25565 |
| 기존 | 학교, 튜토리얼 장소, 스토리, NPC, 상점 | school | 12GB | 25566 |
| 기존 | 큐디치 | arena1 | 7GB | 25673 |
| 기존 | 1:1 대전 | arena2 | 7GB | 25682 |
| 신규: 24GB / i9-14900K / 6코어 | 야생1 | wild1 | 8GB | 25671 |
| 신규 | 야생2 | wild2 | 8GB | 25681 |

공용 MariaDB와 Redis는 기존 호스트에 유지한다. 기존 Java 힙 합계 27GB 외 약 5GB를 OS, JVM 네이티브 메모리, DB, Redis가 함께 사용한다. 신규 Java 힙 합계 16GB 외 약 8GB도 예약된 보장치가 아니라 잔여 용량이며 실사용 검증이 필요하다.

## 라우팅

Velocity에서 school은 로컬 25566, arena1은 로컬 25673, arena2는 로컬 25682를 가리킨다. wild1과 wild2는 신규 호스트의 25671과 25681을 가리킨다. 실제 호스트 주소는 운영 환경 변수/별도 운영 인벤토리로 제공한다.

사용 서버 ID는 `school,wild1,wild2,arena1,arena2`로 통일한다. 기존 `wild`, `arena`, `tutorial` 이름을 새 설정에 혼용하지 않는다. tutorial-servers는 비운다. 큐디치 이동 대상은 arena1, duel 이동 대상은 arena2이다.

## 역할 분리

튜토리얼 전용 서버는 폐지하며, 튜토리얼 장소와 진행은 학교에서 운영한다. 던전 전용 서버는 현재 범위 밖이다. 야생은 기존 지형을 재사용하지 않고 데이터팩만 옮겨 새 월드를 생성한다. 아레나 경기장 좌표, 매칭 활성화, 경기별 설정은 서버 기동과 별개로 검증한다.

## 공통 서비스

- 채팅, 파티, 신뢰 서버 및 이동 목록에 실제 다섯 서버 ID를 반영한다.
- wild2는 아레나로 잘못 표시하지 않고 별도 야생2 이름으로 처리한다.
- 권한은 LuckPerms 공용 MariaDB 사용을 기준으로 한다.
- 플레이어 인벤토리 등 동기화는 HuskSync 및 각 플러그인의 저장 범위를 구분한다.
- 가방은 별도 소유권 lease를 사용한다. 접속 해제, 튕김, 서버 이동, 빠른 재접속 시 저장/회수의 멱등성과 이전 세션·신규 세션 경계를 검증해야 한다.
- 닉네임·친구·칭호·퀘스트는 공용화 대상이지만, 배포 기록상 아레나 일부가 로컬 SQLite 상태여서 전체 완료로 표시할 수 없다.
- 공통 아이템 정의와 모델 ID 매핑은 일치시킨다. 서버별 ItemsAdder ID 캐시 충돌을 초기화로 무작정 해결하지 않는다.

## 기본 운영값

Java 21. 학교 view-distance=16, 야생 view-distance=12. 후원 플러그인은 필요한 백엔드에 배포하되 후원 처리 서버 목록에서 PvP/아레나는 제외한다. 런처 모드와 서버 플러그인이 짝을 이루는 기능은 동일 릴리스에서 배포한다.

## 점검 모드

외부 접속 제어는 프록시 점검 모드를 우선 관리한다. 백엔드의 별도 점검 모드는 프록시 허용 목록을 자동으로 공유하지 않으므로 중복 차단을 주의한다. 프록시에서 허용되더라도 백엔드가 별도로 거부할 수 있다. 현재 보안 정책이나 방화벽 설정 변경을 이 문서만으로 승인하지 않는다.

## 오픈 전 검증 기준

- [ ] 다섯 서버의 접속 및 왕복 이동
- [ ] 일반 사용자와 운영자 명령 실행
- [ ] 이동 전후 인벤토리, 가방, 권한, 칭호 일관성
- [ ] 전체 채팅의 서버 표시와 전달 범위
- [ ] 큐디치와 1:1 매칭 대상 및 경기장 설정
- [ ] DB 풀 전체 합계, 실연결 수, 메모리 여유
- [ ] 접속 종료/비정상 단절/빠른 재접속/서버 이동 후 가방 lease 회수
- [ ] 런처 신규 설치와 기존 설치 업데이트
- [ ] 실제 클라이언트의 모든 필수 VFX 준비 완료 및 마법 시전
- [ ] NPC/대화/아이템 리소스 표시와 자동 활성화

## 기록상 미완료/주의

가방 재발 방지 v6 후보는 22개 집중 테스트 통과 기록이 있지만 운영 적용은 확인되지 않았다. VFX 수정은 376팩·1537시스템 파싱 및 서버 필수834개 누락0으로 배포되었지만, 최신 클라이언트의 실제 시전 검증은 별도로 필요하다. 신규 호스트와 아레나의 공용 데이터 저장 방식, ItemsAdder 캐시 충돌, 경기장 설정은 개별 완료 증거가 필요하다.
