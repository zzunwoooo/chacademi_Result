# Magic Codex UI · Fabric 1.21.4

마법학교 도감을 화면에 띄우고 카드·카테고리·필터·검색·페이지를 조작하는 클라이언트 전용 모드다. **0.6.5는 YAML 마나 비용을 도감 상세 정보에 표시하는 버전이다.** 로컬 YAML과 서버 권한을 이용하고 최대 6개의 마법 키 설정을 저장한다. 기증 처리는 아직 연결하지 않았다. 플러그인에 연결되지 않으면 도감 대신 연결 안내를 표시한다.

## 설치

1. Minecraft **1.21.4**, Fabric Loader **0.16.14 이상**, Java **21**을 사용한다.
2. 게임 프로필의 `mods` 폴더에 `magic-codex-ui-0.7.0+mc1.21.4.jar`와 **Fabric API 0.119.4+1.21.4**를 넣는다. 이전 Magic Codex JAR는 빼고 교체한다. 같은 버전의 Fabric API가 이미 있으면 중복으로 넣지 않는다.
3. 싱글플레이 또는 서버에 접속한 뒤 채팅창에 `/화면`를 입력한다. 서버의 Paper `plugins` 폴더에 넣는 파일이 아니다.
4. 권한 연동은 Paper 서버의 `plugins/`에 `magic-codex-bridge-0.4.1.jar`를 설치하고 서버를 재시작해야 한다. 기존 클라이언트 YAML은 수정 없이 사용한다.

## 조작

| 입력 | 동작 |
| --- | --- |
| `/화면` | 도감 표시 켜기/끄기 |
| I | 도감 열기. 도감에서 검색 중이 아니면 닫기. Minecraft 조작 설정에서 변경 가능 |
| Z | 마법 사용 ON/OFF. 접속 시 OFF로 시작 |
| 저장한 마법 키 | ON일 때 해당 YAML의 `cast.command`를 플레이어 명령으로 전송 |
| 도감 상단 키 설정 | 키보드형 마법 키 설정 화면으로 이동 |
| `/화면 켜기` | 도감 표시 켜기 |
| `/화면 끄기` | 도감 표시 끄기 |
| `/화면 새로고침` | 로컬 YAML 목록 다시 읽기. 관리자 권한 불필요 |
| 도감에서 `/` | 명령어 입력창 열기. 여기서 `/화면`를 다시 입력해 끌 수 있다. |
| 도감에서 채팅 키(기본 T) | 채팅창 열기 |
| 도감에서 ESC | 도감 닫기 |
| 마법 카드 클릭 | 선택 테두리 및 오른쪽 상세 정보 표시 |
| 왼쪽 카테고리 클릭 | 전체·바람·화염·물·대지·빛·어둠으로 목록 변경 |

서버 명령 권한이나 OP는 필요하지 않다. 검색 중에는 T와 /도 검색어로 입력된다. 검색창 밖을 클릭하거나 Enter로 입력을 끝내면 채팅 단축키를 사용할 수 있다. 서버를 나가거나 월드를 종료하면 표시 상태는 초기화된다. 화면은 게임을 일시정지하지 않는다. 도감을 새로 열면 전체 목록으로 시작한다.

## 화면

첫 UI 원본 PNG(1672×941)와 다운로드한 마루 부리·Pretendard TTF를 사용한다. 화면 종횡비를 유지해 중앙에 맞추며, 울트라와이드·4:3 화면에서는 여백이 생긴다. 창 크기나 Minecraft GUI 배율이 변경되면 다시 계산한다. 배경과 글자가 같은 좌표계로 움직인다.

처음 실행하면 기본 마법 18개의 YAML 파일을 만든다. 이미 `spells` 폴더가 있다면 파일을 덮어쓰거나 삭제한 예시를 복원하지 않는다. 런처에서 미리 배포한 목록도 그대로 사용한다. 이름·설명·조건 안내·연구 기록·카테고리·쿨다운 표시는 YAML에서 읽는다. 권한 응답을 받기 전에는 **미확인**, 응답 이후에는 **발견·미발견**으로 표시하며 해당 필터와 게이지도 함께 갱신한다. 권한이 없거나 미확인인 마법은 발견 조건 문구와 체크칸을 숨긴다.

기본 그림 18종은 기존 아틀라스에서 크기 변경 없이 분리한 PNG로 모드에 포함된다. `icon` 경로는 실제 Minecraft 리소스를 가리킨다. 모드나 활성 리소스팩에 없는 이미지이면 해당 속성 문양을 대신 표시하고 로그에 누락 경로를 남긴다. `config`에 PNG를 넣는 것만으로는 읽지 않는다.

카드를 선택하면 오른쪽의 이름·속성·설명·재사용 시간·발견 조건·연구 기록이 함께 바뀐다. 카테고리·필터·검색·페이지 변경 시 이전 선택을 지워 다른 목록의 정보가 남지 않게 했다. 결과가 없는 칸은 선택할 수 없고 안내 문구가 나타난다. 검색과 발견 필터는 카테고리를 바꿔도 유지된다.

기증 버튼은 준비 중 안내만 표시한다. `cast.command`는 마법 ON 상태에서 해당 등록 키를 눌렀을 때 실행한다. `permission` 값은 도감 또는 마법 모드에서 서버 권한을 확인하는 데 사용한다. 권한 지급·회수는 기존 서버 권한 시스템에서 담당하며 도감 모드와 연동 플러그인은 권한을 변경하지 않는다.

### 0.6.4 도감·키 설정 이미지 렌더러 통일

도감 배경·카드·선택 프레임·문양·버튼·아이콘과 키 설정 배경·아이콘을 핫바와 같은 알파 보정 밉맵/trilinear 경로로 그린다. PNG 파일은 재가공하지 않았다. 여러 요소가 들어 있는 아틀라스는 사용할 영역을 먼저 분리한 후 밉맵을 생성해 이웃 그림의 색이 섞이지 않게 한다.

도감은 기존 맞춤 배율의 85%로 중앙에 표시한다. 클릭·마우스 오버·검색·스크롤 좌표도 같은 배율로 환산한다. 글씨는 변경된 화면 크기에 맞춰 기존 폰트 렌더러로 다시 그린다. 키 설정 화면과 우하단 핫바 크기는 그대로다.

이미지와 영역별 GPU 텍스처는 캐시한다. 한 프레임에서 같은 아틀라스를 여러 번 읽지 않으며 업로드 후 디코딩한 원본은 해제한다. 128개를 넘으면 최근 프레임에서 쓰지 않은 텍스처를 다음 프레임 시작에 정리한다. 화면 종료·리소스 새로고침 시 해당 캐시를 해제한다. 새로운 서버 통신은 없다. 기존 플러그인 0.4.1, 마법 YAML, 키 설정 파일을 그대로 사용한다.

검증: 자동 검사 95개, 별도 Fabric 개발 클라이언트의 카드·카테고리·필터·검색·페이지·키 설정·HUD 회귀 검사. 각 화면의 GPU 축소 필터와 마지막 1px 밉 레벨도 확인한다. 실제 운영 서버에서의 시전 검사는 포함하지 않는다.

### 0.6.3 핫바 전용 렌더러 (이전 버전)

0.6.2의 PNG 원본·배치·표시 크기·색상은 유지했다. 기존의 밉맵 없는 bilinear 필터 대신 핫바 프레임과 마법 아이콘에 전용 GPU 텍스처를 만들고, 전체 밉맵 체인과 trilinear 필터를 적용한다. 축소 시 원본의 소수 픽셀만 샘플링하던 방식에서 여러 픽셀의 기여를 합친 축소 단계를 사용하게 된다.

원본 파일은 수정하지 않는다. 메모리에서 RGB를 알파로 가중한 뒤 밉맵을 만들고, 전용 premultiplied-alpha 셰이더와 블렌딩으로 합성한다. 투명 픽셀에 남은 RGB가 테두리에 섞이거나 투명도를 두 번 적용해 어두워지는 것을 방지한다. 회색/OFF 틴트도 동일한 합성 규칙을 따른다. 원형 바탕·진행 호·금선에는 실제 화면 픽셀 기준으로 알파가 변하는 가장자리를 추가한다.

준비한 텍스처와 밉맵은 재사용한다. 같은 프레임 PNG를 슬롯마다 업로드하지 않고 리소스 교체·접속 종료 시 정리한다. 많은 마법을 교체하며 쌓인 캐시는 24개를 넘으면 다음 프레임 시작에 비운다. 기본 Minecraft 텍스처·도감·폰트의 필터를 전역 변경하지 않고 핫바 전용 경로에만 적용한다. 새 서버 통신은 없다.

개발용 비교 화면은 같은 원본 PNG를 같은 크기로 기존 bilinear 방식과 새 방식으로 각각 그린다. GPU의 실제 `GL_LINEAR_MIPMAP_LINEAR` 설정 및 마지막 밉 레벨 1px 할당을 확인한다.

### 0.6.2 핫바 크기와 선명도

핫바 전체 배율을 25% 키워 아이콘·지정 키·쿨타임 숫자와 별 장식이 함께 커지게 했다. 1672×941 화면 기준 원의 지름은 약 53에서 67px로 증가한다. 1254×1254 PNG 원본은 그대로 사용하며 금색 외곽선을 0.6에서 1.3, 안쪽 선을 0.4에서 0.75 원본 UI 단위로 굵게 그린다. 확대 배율까지 반영하면 이전 대비 외곽선 두께는 약 2.7배다.

금선과 별의 밝기, OFF·빈 슬롯 테두리의 대비를 높였다. 원 바탕을 조금 더 진하게 하고 외곽에 얇은 어두운 선을 넣어 밝은 블록 위에서도 윤곽을 구분한다. 우하단 정렬과 기본 핫바 겹침 방지는 유지하며 서버 통신·시전 동작·YAML 형식은 변경하지 않는다.

### 0.6.1 원형 마법 핫바

작은 6칸 배치를 유지하며, 네모 바탕을 원형 반투명 바탕과 투명 금빛 마법진 PNG로 교체했다. 작은 별 장식과 금속 느낌의 키 캡을 추가하고 Z 상태 옆에 작은 마름모를 표시한다. 원형 마법진은 같은 고해상도 리소스를 재사용하며, 마법 아이콘·지정 키·쿨타임·ON/OFF는 동적으로 표시한다. 빈 슬롯과 OFF 상태에서는 장식도 어둡게 표시한다.

쿨타임은 12시 방향에서 시작하는 원형 덮개와 은청색 호가 시계 방향으로 줄어든다. 96분할 좌표를 미리 계산해 사용하고 매 프레임 이미지나 텍스처를 생성하지 않는다. 숫자 표시는 기존 글자 캐시를 재사용한다. 기존 시전·권한 구독·입력 차단·파일 형식과 bridge 0.4.1은 유지한다.

### 0.6.0 마법 모드와 스킬창

키 설정에서 마법과 키를 저장한 뒤 도감을 닫고 **Z**를 누른다. 우하단에 큰 바깥 테두리 없이 6칸과 실제 지정 키, Z · ON/OFF가 표시된다. OFF에서는 아이콘을 흐리게 남긴다. F1이나 다른 화면을 열면 스킬창을 숨긴다. 화면 크기에 맞춰 배치하고 큰 GUI 배율에서는 기본 핫바 위로 올려 겹침을 피한다.

- ON에서만 등록 키로 서버에 플레이어 명령을 전송한다. 예: `command: cast magicalflame` → `/cast magicalflame`. 콘솔/OP 실행이 아니며 실제 스킬은 기존 서버 스크립트와 MythicMobs에서 처리한다.
- 등록 키에 겹치는 바닐라 동작은 ON에서 차단한다. OFF에서는 평소 조작으로 돌아간다. 채팅·도감·키 설정·메뉴에서 마법을 발동하지 않는다. 누르고 있는 키는 반복 시전하지 않는다.
- 쿨타임은 YAML의 `cast.cooldown-seconds`만 사용한다. 명령을 보낸 시점부터 어두운 덮개와 남은 초가 표시되며 10초 미만은 소수 첫째 자리로 표시한다. 쿨타임 중 재입력을 막는다. OFF 전환, 키 변경, 도감 열기, YAML 새로 읽기로 남은 쿨타임을 초기화하지 않는다.
- 서버의 실제 성공/실패·쿨타임을 동기화하지 않는다. 서버에서 명령이 거절되어도 로컬 표시는 시작하며, 재접속하면 로컬 쿨타임이 초기화된다. 실제 권한과 쿨타임 제한은 서버의 명령/스킬에서 검증한다.
- 미확인·미보유·삭제된 마법, 명령이 비어 있는 마법은 실행하지 않는다. 권한 확인 중 아이콘은 흐리게 표시된다.
- 도감을 열면 전체 목록을 구독하고, 도감을 닫은 채 ON이면 등록된 최대 6개 권한만 구독한다. OFF이고 도감도 닫혀 있으면 구독을 종료한다. 매 시전마다 권한 조회 패킷을 추가로 보내거나 쿨타임 패킷을 보내지 않는다.
- 사망·관전 상태에서는 OFF로 바뀐다. 재접속해도 키 설정은 유지하고 모드는 OFF로 시작한다.
- 기존 **bridge 0.4.1**, YAML, 키 설정 파일을 그대로 사용한다. 이번 배포는 클라이언트만 교체한다.

자동 검사 85개와 별도 Fabric 개발 클라이언트의 도감·키 설정 회귀 검사, 1280×720/1920×1080 스킬창 렌더링을 수행했다. HUD 확인 화면은 명령 전송을 수집하는 개발용 화면이며 배포 JAR에 들어가지 않는다. 실제 Paper/MythicMobs 스킬 시전은 운영 서버에서 별도 확인해야 한다.

### 0.5.3 도감 단축키

I 열기를 기존 `KeyBinding.wasPressed()` 결과 대신 실제 키 입력 콜백에서 처리한다. 같은 키에 다른 단축키가 등록되어 Minecraft의 키 조회를 차지하더라도 도감 열기 요청을 별도로 받는다. Minecraft 조작 설정에서 변경한 도감 키를 따르며, 미지정 상태를 강제로 덮어쓰지 않는다.

월드에 접속하고 다른 화면이 없을 때만 입력을 받으며, 누르고 있는 동안의 반복 입력은 무시한다. 채팅·검색·다른 메뉴에서 입력을 가로채지 않는다. 창 포커스를 잃거나 접속이 끊어지면 누름 상태를 초기화한다. Z 전환과 마법 시전은 이번 변경 범위에 포함하지 않는다.

### 0.5.2 문구와 간격 정리

- 좌상단 학교 이름과 붉은 키 안내 문장을 제거했다. 예약 키의 붉은 강조는 유지한다.
- 기본 안내는 **우클릭으로 등록 해제** 한 줄로 통일했다. 정상 선택·키 변경·초기화 시 긴 안내 문장을 표시하지 않는다. 오류와 권한 확인 중 안내는 필요한 때에만 표시한다.
- 등록 프레임·아이콘·키 표시를 위로 18px 이동하고 툴팁과 저장 팝업 위치도 조정했다.
- 닫기 확인창 버튼은 **계속 설정 / 변경 취소**다. 변경 취소는 저장하지 않은 변경을 취소하고 도감으로 돌아가며, 저장 파일은 유지한다.

### 0.5.1 키 설정 화면 조정

- 좌상단에 학교 이름 **차카데미아**를 표시한다.
- WASD·I·Z를 붉은 배경/테두리/글자와 **지정 불가** 문구로 구분한다.
- 등록 슬롯 프레임은 122×116에서 92×88, 내부 아이콘은 98에서 70으로 줄였다. 상시 마법 이름은 제거하고 슬롯 위에 마우스를 올릴 때 툴팁으로 표시한다. 키 칸은 90×30으로 늘려 긴 키 이름도 들어가게 했다.
- 저장 성공 문구는 창의 안내 줄에서 제거하고 독립된 작은 팝업으로 표시한다. 0.18초 페이드 인, 1.82초 유지, 0.4초 페이드 아웃으로 총 2.4초 뒤 사라진다. 팝업은 클릭을 막거나 입력 포커스를 가져가지 않는다.
- 기존 키 설정 파일과 서버 플러그인 0.4.1은 그대로 사용한다.

### 0.5.0 키 설정

`I` 또는 `/화면` → 상단 **키 설정** → 빈 슬롯 클릭 → 배운 마법 선택 → 키보드 그림을 클릭하거나 실제 키 입력 → **저장** 순서로 사용한다.

- 최대 6개. 같은 마법이나 같은 키를 중복 등록할 수 없다.
- 등록된 슬롯을 클릭하면 키를 변경한다. 슬롯 아래 작은 키 칸을 클릭하면 마법을 교체한다. 우클릭하면 등록을 해제한다.
- 마법 선택창에서 이름을 입력해 검색한다. Backspace로 지우고, 화살표 버튼이나 휠로 페이지를 넘긴다. ESC로 선택을 취소한다.
- WASD, I, Z는 예약되어 있으며 Shift/Ctrl/Alt/Win/Caps Lock 같은 보조 키도 등록할 수 없다. 이번 버전은 화면에 보이는 단일 키만 지원하며 조합키·마우스 버튼·F키는 지원하지 않는다.
- 키/슬롯/버튼에 마우스 강조가 표시되고 선택·등록·저장·오류에 클릭 사운드가 난다.
- 저장 위치는 **`config/magiccodex/key-settings.yml`**. 6개 슬롯의 마법 ID와 실제 키 코드를 보관한다. 저장 시에만 파일을 기록하며 매 프레임 파일을 읽지 않는다.
- 초기화도 저장 전에는 임시 변경이다. 저장하지 않은 채 닫으면 변경을 버릴지 확인한다. 저장 실패 시 이전 파일을 유지한다.
- 권한 미확인·미보유 마법은 새로 선택할 수 없다. 기존 등록 마법이 삭제되거나 권한을 잃어도 설정을 자동 삭제하지 않고 사용 불가로 표시한다.
- 키 설정 화면으로 이동할 때 기존 도감의 권한 구독을 유지한다. 플러그인은 기존 **0.4.1**을 그대로 사용하며 서버 파일 변경이 필요 없다.
- **이번 버전은 설정까지만 구현했다. Z 모드 전환, 실제 cast 명령 실행, 바닐라 중복 키 차단, 우하단 스킬 HUD와 쿨타임 연출은 다음 단계다.** 플레이 중에는 등록한 키가 바닐라 동작을 변경하지 않는다.

### 0.4.1 초기 응답과 로딩 연출

첫 권한 조회를 서버의 1초 주기 작업까지 기다리던 흐름을 바꿨다. 플러그인은 첫 OPEN을 다음 서버 틱에 처리하며 같은 틱의 요청을 합친다. 기존 1초 조회 한도는 정기 작업과 공유하므로 작업 횟수가 늘어도 허용되는 조회 총량은 늘어나지 않는다. 한도를 소진했거나 서버가 지연된 경우에는 더 기다릴 수 있다.

모드는 권한 응답 전에는 회전하는 금색 문양과 로딩 안내를 표시한다. 미확인 카드와 발견 조건을 먼저 노출하지 않으며, 응답 뒤 0.18초 페이드로 도감을 보여 준다. 기다리는 동안 카드·필터·검색은 조작할 수 없고 ESC·X로 닫을 수 있다. 서버 연결이 없거나 오래 지연되면 안내 문구가 바뀐다. 이 변경은 캐시된 습득 결과를 먼저 표시하는 방식이 아니며, 매번 현재 서버의 확인 결과로 시작한다.

### 0.4.0 권한 확인 연동

도감이 열려 있을 때만 구독하고, YAML에 지정된 중복 없는 권한 이름을 서버에 보낸다. 서버는 실제 권한을 확인해 작은 비트 목록으로 응답한다. 결과가 같으면 재전송하지 않는다. 열린 도감에서는 권한 지급·회수 시 카드 표시, 필터, 선택된 마법의 상세 정보와 숨겨진 발견 조건이 함께 갱신된다.

도감을 닫거나 서버 연결이 바뀌면 확인 결과를 지운다. 다시 열기 및 YAML 다시 읽기는 새 요청 번호를 사용하므로 이전 응답을 새 목록에 적용하지 않는다. 도감이 열린 동안만 15초마다 작은 유지 신호를 보내며, 평상시에 권한 목록을 반복 요청하지 않는다. 최초 응답이 없을 때만 제한된 간격으로 재시도한다.

플러그인은 기본 1초당 최대 2,048회의 조회를 처리한다. LuckPerms 권한 재계산 알림을 모아서 처리하고, 그 외 변경은 열린 도감만 기본 10초마다 확인한다. 실제 반영 지연은 서버 TPS와 대기 요청 수에 따라 달라진다. 플러그인의 자세한 설정과 설치 방법은 함께 제공한 `magic-codex-paper/README.md`를 참고한다.

### 0.3.1 발견 조건 표시

발견 조건 문구와 체크칸은 습득 상태가 확인된 보유 마법에만 표시한다. 미보유 또는 미확인 상태에서는 해당 내용 대신 ‘습득 후 확인할 수 있습니다.’를 표시한다. YAML의 조건 문구는 유지하며, 마법 설명과 연구 기록의 표시 방식은 동일하다. 현재 서버 권한 연동 전이므로 일반 도감에서는 모든 마법의 조건이 숨겨진다.

### 0.3.0 로컬 YAML 읽기

마법 하나당 `.yml` 또는 `.yaml` 파일 하나를 `config/magiccodex/spells/`에 둔다. UTF-8과 공백 들여쓰기를 사용한다. 하위 폴더는 읽지 않는다. `order`가 작은 순서로 정렬하며 같으면 `id` 순서로 정렬한다. 최대 256개, 파일당 64KB다. 시작할 때 한 번 읽어 메모리에 보관하며 화면을 그릴 때마다 파일을 다시 읽지 않는다.

```yaml
id: magical_flame
name: 작은 불씨
description: |-
  손끝에서 작은 불씨를 피워냅니다.
  어두운 교실을 밝힐 수 있습니다.
category: fire
icon: magiccodex:textures/spells/magical_flame.png
permission: magic.learned.magical_flame
discovery:
  description: 불이 붙은 상태로 30초 버티기
research: 화염 수업에서 발견한 첫 번째 마법.
cast:
  command: cast magicalflame
  cooldown-seconds: 10
order: 10
```

필수 항목은 `id`, `name`, `category`, `icon`, `permission`, `discovery.description`이다. 나머지는 생략할 수 있다. 이전 `circle`과 `rank`는 무시한다. `cooldown-seconds`와 `order`는 0, 설명·연구 기록·명령은 빈 문자열로 처리한다. `category`는 `wind`, `fire`, `water`, `earth`, `light`, `dark` 중 하나다. `id`는 소문자·숫자·밑줄·하이픈만 사용한다. 명령은 `/` 없이 한 줄로 적는다. 조건 문구는 표시용이며 행동을 자동 판정하는 조건식이 아니다.

파일을 추가·수정·삭제한 뒤 `/화면 새로고침`를 입력한다. 잘못된 문법·중복 ID·중복 키·오타 필드·잘못된 카테고리 등이 있으면 해당 파일명과 이유를 채팅 및 `logs/latest.log`에 표시하며 **직전에 정상적으로 읽은 전체 목록을 유지**한다. 시작부터 오류가 있으면 빈 도감과 오류 안내가 표시된다. 폴더를 비우고 다시 읽으면 빈 도감이 되며 예시를 자동 복구하지 않는다.

배경·버튼의 배치와 사운드는 0.2.7 구성을 사용한다. 긴 이름은 영역을 벗어나지 않도록 말줄임 처리하며, 설명과 조건의 줄바꿈을 지원한다. 이름은 최대 64자, 설명 1024자, 조건 및 연구 기록 512자이며 화면에서는 기존처럼 정해진 줄 수 안에 표시한다.

각 플레이어는 런처를 통해 같은 YAML과 이미지 리소스를 받으면 된다. 0.3.0에서는 서버 연동을 제외했고, 0.4.0부터 별도 플러그인으로 권한을 확인한다.

### 0.2.7 그림 위치와 조작 소리

카드 그림 중심을 4 올리고 크기를 120→112로 살짝 줄여 위쪽 테두리의 여백도 유지했다. 상세 그림은 크기를 유지하며 8 올렸고, 잠금 표시는 그림을 따라 이동한다. 기증 버튼은 아이콘과 글씨를 10 간격의 한 묶음으로 배치하고 실제 글자 너비를 기준으로 버튼 가운데에 맞춘다. 수치는 원본 UI 좌표 기준이다.

카테고리·필터·검색창에는 작은 클릭음, 카드 선택에는 약간 높은 클릭음, 페이지 이동에는 책장 넘기는 소리, X·ESC 닫기에는 책을 내려놓는 소리를 연결했다. 기증 안내는 낮고 짧은 클릭음으로 구분한다. Minecraft 기본 소리를 낮은 음량으로 사용하며 마스터 음량 설정을 따른다. 같은 선택을 다시 누르거나 빈 카드·이동할 수 없는 페이지를 누를 때에는 소리를 내지 않고, 빠르게 반복되는 동일 소리는 0.1초 간격으로 제한한다.

### 0.2.6 전체 배치와 카드 비율 통일

서로 다른 높이의 기존 카드에 하단 기준 좌표를 적용해 마지막 줄 이름이 그림에 닿던 문제를 고쳤다. 아홉 카드 모두 같은 원본 카드 부분을 표시해 208×186 크기, 가로·세로 14 간격으로 통일했다. 그림 끝, 이름, 배지의 영역을 따로 정했으며 클릭 영역도 같은 배치 정의를 사용한다. 실제 한글 글리프 높이를 기준으로 그림과 이름 사이, 이름과 배지 사이, 배지와 카드 바닥 사이에 여백이 남는지 검사한다.

왼쪽 아래 책 문장을 32 아래로, 오른쪽 위 게이지 그림과 채움을 18 아래로, 발견 수 문구를 15 아래로 옮겼다. 도감 부제는 오른쪽으로 15 이동했다. 기존 PNG 파일은 수정하지 않고 필요한 원본 영역을 화면에서 재배치한다.

상세 마법 이름과 설명의 중심 간격은 45→33, 설명 줄 간격은 30→27로 줄였다. 속성 태그는 166×34→136×28, 글씨는 18→16으로 축소했다. 상세 정보의 왼쪽 기준선을 맞추고 체크칸·책 문양 크기와 기증 버튼의 아이콘·글자 간격도 정리했다. 수치는 UI 원본 좌표 기준이다.

### 0.2.5 카드 내용의 아래쪽 넘침 조정

카드의 마법 아이콘 중심을 6 올리고 크기를 140→120으로 줄여 그림 영역 안의 여백을 확보했다. 미발견 잠금 표시도 8 올렸다. 이름·배지를 6 올리고 배지 높이를 23→20, 배지 글씨를 17→16으로 조정했다. 높이가 다른 마지막 줄을 포함해 배지는 각 카드 하단에서 10의 여백을 두고 끝난다. 수치는 원본 좌표 기준이다. 상세 화면의 큰 마법 그림과 정보 배치, 클릭 좌표는 유지했다.

### 0.2.4 투명 배지와 글씨 비중 정리

왼쪽 아래 격언과 상단의 장식용 격언을 제거했다. 발견·미발견 배지와 속성 태그는 새로운 독립 RGBA PNG를 사용한다. 기존 배경에서 캡슐을 잘라 그릴 때 함께 복사되던 사각형 양피지가 더 이상 포함되지 않는다. PNG는 `badge_discovered.png`, `badge_undiscovered.png`, `tag_category.png`로 분리했고, 둥근 모서리 바깥의 알파 0을 자동 검사한다.

카드 마법 이름은 22→20, 상세 이름은 최대 36→28로 줄였다. 도감 제목은 40, 카테고리는 21, 속성 태그는 18, 상세 설명은 21, 기증 버튼은 26으로 비중을 정리했다. ‘발견 조건’과 ‘연구 기록’ 제목은 22를 유지하되 마루부리 Bold TTF로 강조한다. 수치는 원본 좌표 기준이며 화면 배율에 맞춰 표시한다. 기존 클릭 기능과 마법 그림, 전체 배경은 유지했다.

새 PNG와 생성 프롬프트, 좌표 및 글씨 크기 표는 `output/magic-codex-ui/components-v4/`에 보관한다.

### 0.2.3 첫 시안의 그림과 정보 구성 복원

첫 시안과 게임 화면을 비교해 빠져 있던 전용 마법 일러스트 18종, 카테고리 문양 7종, 상세 화면의 큰 그림과 원형 금장 문양을 넣었다. 미발견 그림은 색을 어둡게 낮추고 잠금 PNG를 겹친다. 카드 발견 배지와 상세 속성 태그는 원본 UI의 캡슐 그림을 재사용해 테두리 두께를 맞췄다. 완료/미완료 체크칸은 앞서 제작한 독립 PNG를 연결했다. 연구 기록의 책 문양과 기증 버튼의 나침반 문양도 표시한다.

제목은 원본 좌표 기준 44로 키웠으며, 상세 마법 이름·속성 태그를 큰 그림 아래 한 줄에 배치했다. 카드 이름 아래에는 발견 여부를 짧은 배지로 표시하고, 속성은 그림 왼쪽 위 문양과 상세 태그로 구분한다. 0.2.2의 글자 렌더링과 선택 금장 프레임, 9칸 배경 PNG와 클릭 좌표는 유지했다. 그림 원본은 축소 저장하지 않고 원래 PNG를 사용한다.

출시 전까지는 확인용 마법 데이터다. 예시 그림을 연결한 것이며 YAML·서버 동기화·마법 효과를 새로 구현한 버전은 아니다. 생성 프롬프트와 첫 시안 비교 기록은 `output/magic-codex-ui/components-v3/`에 보관한다.

### 0.2.2 자연스러운 글자와 선택 프레임

제목·마법 이름은 마루 부리 SemiBold, 본문은 Pretendard Regular, 조작용 글씨는 Pretendard Medium으로 조정했다. 도감의 글자는 실제 화면 픽셀 크기에 맞춰 Java의 글꼴 렌더러로 안티앨리어싱한 뒤 RGBA 텍스처로 표시한다. 입력 문자열·설명·필터 결과는 계속 동적으로 바뀐다. 화면 배율·문구별 결과를 재사용하고 화면을 닫거나 크기를 바꾸면 관련 텍스처를 해제한다. 이 방식은 도감 글자에만 적용된다.

카드의 선택·마우스 올림 표시는 새 투명 금장 PNG(`textures/gui/card_selected.png`, 1254×1254)를 사용한다. 선택 시 원래 밝기로, 마우스를 올리면 낮은 불투명도로 표시한다. 바깥 여백과 중앙 구멍은 투명해서 카드 아이콘과 글씨를 가리지 않는다. 기존 배경 PNG와 클릭 좌표는 유지했다.

글꼴은 설치된 OS 폰트가 아니라 모드에 포함된 TTF에서 불러온다. TTF 리소스를 교체했을 때에는 리소스를 다시 로드한 뒤 도감을 닫고 다시 열면 된다. Java 21의 표준 `java.desktop` 글꼴 기능을 사용한다.

### 0.2.1 글자 가독성 개선

제목과 마법 이름에는 마루 부리 Bold를, 설명·버튼·카테고리·보조 정보에는 Pretendard Medium을 사용한다. 카드 보조 글씨는 원본 좌표 기준 15에서 19, 상세 설명은 20에서 22로 키우고 작은 안내 문구도 19 이상으로 조정했다. 보조 글씨 색의 대비를 높였으며 발견 조건과 연구 기록은 두 줄까지 표시한다.

작은 화면에서 큰 글리프 이미지를 과도하게 축소하지 않도록 TTF 오버샘플링을 4에서 2로 조정하고 선형 필터링은 유지했다. 텍스트 원점은 GUI 배율 적용 후 실제 화면 픽셀에 맞춘다. 검색창 글씨 크기와 커서·선택·클릭 계산은 같은 크기를 사용하며, 긴 검색어는 입력 영역 너비에 맞춘다. 글자가 아닌 아이템 아이콘의 픽셀 스타일과 기존 배경 PNG는 그대로다.

### 0.2.0 클릭 연결

그리기와 클릭 판정이 같은 원본 PNG 좌표를 사용한다. 해상도나 GUI 배율 변경 시 마우스 위치를 해당 좌표로 변환한다. 카드·카테고리에는 마우스 올림 및 선택 표시가 있고, 유효한 클릭에는 소리가 난다. 기존 배경 디자인과 1672×941 해상도는 유지했다.

### 0.1.1 표시 개선

- 실제 렌더링되는 글자 영역으로 세로·가로 중심을 계산한다. 제목·카테고리·필터·기증 버튼·페이지 번호의 크기와 위치를 조정했다.
- TTF 오버샘플링을 2에서 4로 높였다. 도감 전용 폰트와 배경에 선형 필터링을 적용해 비정수 배율에서 거친 가장자리를 줄인다. 기본 게임 글꼴에는 적용하지 않는다.
- 배경 PNG 원본은 1672×941 그대로다. 필터링은 계단 현상을 줄이며 원본에 없는 디테일을 만들지는 않는다. 큰 화면의 장식 선명도를 더 높이려면 고해상도 원본 또는 별도의 선·프레임 리소스가 필요하다.

## 소스 빌드

소스 ZIP의 `magic-codex-fabric`, `magic-codex-protocol`을 같은 상위 폴더에 둔다. Java 21에서 Fabric 프로젝트의 `gradlew.bat build`를 실행한다. Gradle Wrapper는 8.12.1, Fabric Loom은 1.9.2다. 일부 Windows 환경에서 한글 경로의 Gradle 테스트 프로세스가 실패할 수 있으므로 그 경우 프로젝트와 Gradle 캐시를 영문 경로에 두고 빌드한다.

자동 검사는 화면 배치·원본 PNG·TTF와 함께 카테고리 전환, 어둠 목록, 필터·검색 조합, 빈 목록, 페이지 경계, 선택 초기화, 여러 화면 크기의 클릭 좌표를 검사한다.

`gradlew.bat runVisualTest -PvisualCheck`는 별도 개발 클라이언트에서 화면 클릭·한국어 검색 입력·스크롤 이벤트를 호출하고, 선택 결과와 필터·페이지·닫기 동작을 검사한다. GUI 배율 2·3의 실제 렌더링 화면을 `run/visual-check/`에 저장한 뒤 종료한다. 월드에 접속하지 않는다. 이 검사 전용 모드는 배포 JAR에 포함되지 않는다. 실제 서버 연결과 OS 한글 조합 입력은 이 검사 범위에 포함되지 않는다.

폰트 저작권·라이선스는 `src/main/resources/licenses/`에 있으며 JAR에도 포함된다. 기반 PNG와 폰트는 이 프로젝트 안에 복사되어 원래 생성 이미지 폴더 없이 빌드할 수 있다.
