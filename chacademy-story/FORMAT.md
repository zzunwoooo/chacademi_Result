# 차카데미 컷신 파일 형식 (format 1)

> 2026-10-11 기본 대화 경로 업데이트: 클라이언트 단일 실행·commands·로컬 기록·한정 보상 연결은 [최신 인계 문서](../docs/handoff/CODEX_STORY_LOCAL_20261011.md)를 우선한다. 아래 구형 서버 그래프/ledger 설명은 새 기본 대화의 필수 조건이 아니다.

컷신 하나 = 폴더 하나.

```
.minecraft/config/chaca_cutscene/
  ch1_ashen_night/          ← 폴더 이름 = 컷신 id
    cutscene.yml
    s1_1.png
    s1_2.png
    s2_1.png
  _seen.txt                 ← 이미 본 컷신 목록 (모드가 자동으로 관리)
```

편집기에서 "zip으로 내보내기"를 누르면 이 폴더 구조 그대로 zip이 만들어진다.
zip을 `config/chaca_cutscene/` 안에 풀면 끝. 이미지는 편집기가 PNG로 바꿔서 넣어 준다.

## cutscene.yml

```yaml
format: 1
id: ch1_ashen_night        # 소문자, 숫자, _, - 만. 폴더 이름과 같아야 함
title: 잿빛 밤 동화         # 관리용 이름 (화면에 안 나옴)
font: medium               # 자막 폰트 굵기: light | medium | bold
font_size: 1.0             # 자막 크기 배율 (0.4 ~ 2.5). 1.0 = 아래 띠 높이의 약 1/3
text_color: "#EFE3C8"      # 자막 색
text_x: 0.5                # 자막 가운데의 가로 위치 (0 왼쪽 ~ 1 오른쪽)
text_y: auto               # 세로 위치. auto = 아래 띠 가운데, 숫자 = 화면 높이 비율 (0 위 ~ 1 아래)
text_shadow: false         # 그림 위에 글자를 올릴 때 켜면 잘 보임
italic: true               # 자막 기울임
prefix: "- "               # 모든 자막 앞에 자동으로 붙는 글자
type_speed: 0.06           # 글자 하나가 써지는 시간 (초)
letterbox: 0.14            # 위아래 검은 띠 높이 (화면 높이 대비 비율)
letterbox_time: 1.6        # 띠가 내려오는 시간 (초)
end_fade: 1.2              # 마지막 암전 시간 (초)
type_sound: default        # 글자 써질 때 소리. default = ChacaNPC 대화창과 같은 소리 | none | 마인크래프트 소리 id
type_sound_volume: 0.5     # 0.5 = 대화창과 같은 크기. 1.0 이면 두 배
bgm: bgm.ogg               # 컷신 폴더 안 배경음 (ogg만). 비우면 없음
bgm_volume: 0.6            # 배경음 크기 (0 ~ 1). 마인크래프트 [주 음량]만 곱해짐 ([음악]을 꺼도 들림)
bgm_start: 0               # 곡의 몇 초 지점부터 틀지 (초)
bgm_fade_in: 3.0           # 처음에 소리가 커지는 시간 (초)
bgm_fade_out: 4.0          # 끝나기 전 소리가 줄어드는 시간 (초)
scenes:
  - images: [s1_1.png, s1_2.png, s1_3.png]   # 2장 이상이면 fps 속도로 반복 (불꽃 흔들림 등)
    fps: 6
    duration: 8.0          # 이 장면의 길이 (초)
    zoom:
      x: 0.62              # 줌 중심 (이미지 가로 비율 0~1)
      y: 0.45              # 줌 중심 (이미지 세로 비율 0~1)
      from: 1.0            # 시작 배율
      to: 1.08             # 끝 배율
    transition: ink        # 앞 장면에서 넘어오는 방식: ink | fade | cut
    transition_time: 1.4
    lines:
      - text: 백 년 전, 잿빛 밤.
        start: 1.7         # 장면 시작 기준 (초)
        end: 4.2
```

## 시간 규칙

- 장면은 순서대로 이어진다. 전체 길이 = 모든 장면 duration 합 + end_fade.
- 전환(transition)은 장면이 시작될 때 transition_time 동안 앞 장면 위로 덮인다. 첫 장면은 검은 화면에서 전환된다.
- 줌은 장면 길이 전체에 걸쳐 부드럽게(ease-in-out) from → to로 움직인다.
- 자막은 start에 나타나 type_speed마다 한 글자씩 써지고, end 직전 0.3초 동안 흐려진다.
- 2배속이면 모든 시간이 절반으로 줄어든다.

## 소리

- 타자기 소리는 ChacaNPC 대화창과 같다 (버튼 클릭음, 높이 1.8). 공백에서는 소리가 안 나고, 45ms보다 촘촘하면 건너뛴다.
- 배경음은 bgm_start 지점부터 한 번만 재생된다 (반복 없음). 컷신이 끝나는 시점에 맞춰 bgm_fade_out 동안 천천히 줄어든다.
- 건너뛰거나 서버가 멈추면 1.5초 동안 줄어들며 꺼진다. 컷신 도중에는 바닐라 배경음악이 멈춘다 (배경음이 없는 컷신도).
- ogg 는 32MB 까지. 읽기·디코딩은 화면이 멈추지 않게 작업 스레드에서 한다 (읽지 못하면 배경음 없이 재생).

## 건너뛰기

- 처음 보는 컷신은 건너뛸 수 없다.
- 끝까지 본 컷신은 `_seen.txt`에 기록되고, 다음부터는 스페이스바를 2초 꾹 눌러 건너뛸 수 있다 (원이 차오름).
- 서버 명령어에서 `skip`/`noskip`을 주면 이 규칙을 덮어쓴다.
- 2배속 버튼(>>)은 항상 있다.
- **ESC = 게임 메뉴.** 컷신을 건너뛰는 것이 아니라 잠깐 멈추는 것이다 (언제든 설정을 바꾸거나 접속을 끊을 수 있게). 메뉴가 떠 있는 동안 컷신 시계와 배경음이 멈추고, 메뉴를 닫으면 멈춘 곳부터 이어진다. `noskip` 컷신은 여전히 끝까지 봐야 한다.

## 불러오기 · 숫자 규칙 · 중간에 끊겼을 때

- 재생 신호가 오면 화면(검은 화면 + 레터박스)이 바로 뜨고, yml·PNG·ogg 는 작업 스레드에서 읽는다. 첫 장면이 준비되면 시작한다. 20초 안에 준비되지 않으면 실패로 끝난다.
- 텍스처는 **지금 장면 + 다음 장면**만 올려 두고 지나간 장면은 내린다 (다음 장면 그림이 늦으면 장면 끝에서 잠깐 기다린다). 전환용 텍스처는 전환이 끝나면 바로 내리고, `fade` 는 텍스처를 따로 만들지 않는다.
- 이미지는 PNG, 파일 하나 32MB 까지. 긴 변이 1600px 을 넘으면 줄여서 쓴다 — 편집기가 내보낼 때 미리 1600px 로 줄여 준다. 장면 200개, 장면당 이미지 120장, 자막 200개까지.
- 숫자 자리에 `NaN`·무한대(`.nan`, `.inf`, `"NaN"` …)가 있으면 컷신을 열지 않는다 (끝나지 않는 컷신 방지). 숫자가 아닌 글자는 기본값, 범위를 벗어난 값은 범위 끝으로 자른다. 편집기는 NaN 을 내보내지 않는다.
- 예전 형식의 `image: 파일.png` (한 장) 도 읽는다. `images` 와 같은 이름 검사(경로 불가, PNG만)를 거친다.
- 서버가 재생시킨 컷신이 끝나기 전에 다른 화면에 덮여 사라지면 (사망 화면, 다른 플러그인의 GUI, 월드 이동) 끝난 것이 아니다. 모드가 서버에 "중단됨"을 알리고, 서버가 잠시 뒤 (기본 3초, 최대 5번) 다시 보낸다. 모드는 화면이 비고 살아 있을 때 재생을 시작한다. 접속이 끊겼으면 다음 접속 때 처음부터 다시 재생된다. `on-finish` 는 끝까지 봤을 때 (또는 허용된 건너뛰기) 한 번만 실행된다.
- 클라에 컷신 폴더가 없거나 파일이 깨졌으면 모드가 서버에 "보여 줄 수 없음"을 알린다. 서버는 끝난 것으로 치지 않고 (`on-finish` 실행 안 함) 콘솔에 경고를 남기며 플레이어에게 "스토리 파일이 최신이 아닙니다…" 를 보낸다. 파일을 맞추고 다시 접속하면 이어진다 (config `finish-if-client-content-missing: true` 면 건너뛴 것으로 침).

# 대화 파일 형식 (format 1)

대화 하나 = 폴더 하나. 대화 편집기에서 "zip으로 내보내기"를 누르면 이 구조로 나온다.

```
.minecraft/config/chaca_dialogue/
  ch1_wakeup/                 ← 폴더 이름 = 대화 id
    dialogue.yml              ← 대사, 선택지, 인물, 표정 (클라가 읽음)
    teacher_1.png ...         ← 표정 그림 (PNG)
    server_commands.yml       ← 서버용. 클라에서는 무시

서버: 같은 폴더를 그대로 복사
plugins/ChacademyStory/dialogues/
  ch1_wakeup/
    dialogue.yml              ← 서버가 대화 흐름(선택지·조건·결말)을 검증하는 데 씀. 클라와 같은 파일이어야 함
    server_commands.yml       ← 명령어·호감도
    (png 는 없어도 됨)
```

- zip 을 클라 `config/chaca_dialogue/` 와 서버 `plugins/ChacademyStory/dialogues/` 양쪽에 그대로 풀면 된다. 서버에서는 넣은 뒤 `/서버관리 새로고침 스토리`.
- 예전 위치 `dialogues/<id>.yml` (server_commands.yml 을 이름만 바꾼 것) 도 계속 읽는다. 폴더 안에 `server_commands.yml` 이 있으면 그쪽을 쓴다.
- 서버에 `dialogue.yml` 이 없는 대화는 열리지 않는다 (config `require-server-graph: true` 기본값. 콘솔 경고 + 명령어를 친 사람에게 안내). `false` 로 바꾸면 예전처럼 검증 없이 열린다.

## dialogue.yml

```yaml
format: 1
id: ch1_wakeup
title: "1장 · 깨어남"
start: wake                    # 시작 장면
dim: 0.35                      # (게임에서는 쓰지 않음) 예전 자체 대화창용 값. 아래 "대화창" 참고
type_speed: 0.03               # (게임에서는 쓰지 않음)
type_sound: default            # (게임에서는 쓰지 않음) type_sound_volume 도 같음
speakers:
  me: {name: "{player}"}       # "나". 그림은 ChacaPortrait 로 만든 내 AI 일러스트가 자동으로 나옴
  teacher:
    name: "마중 선생님"
    npc: teacher               # NPC id (호감도용, 선택). ChacaNPC / MagicCodex 와 같은 id
    portraits:                 # 표정 이름: 그림. 첫 번째가 기본
      기본: teacher_1.png
      웃음: teacher_2.png
scenes:
  wake:
    redirect:                  # 들어올 때 호감도가 높으면 다른 장면으로 (위에서부터)
      - {npc: teacher, min: 60, to: wake_friend}
    lines:                     # 한 줄 = 클릭 한 번. face 비우면 앞 표정 유지
      - {who: me, text: "으으… 여기는…?"}
      - {who: teacher, face: 웃음, text: "{player} 씨 맞소?"}
    choices:                   # 최대 6개 (MagicCodex 대화창이 보여 줄 수 있는 수. 넘으면 모드가 대화를 열지 않고 오류를 알림)
      - text: "괜찮아요"
        to: fine               # 비우면 대화 끝
        affinity: [{npc: teacher, add: 2}, {npc: rin, add: -1}]   # 고르면 호감도 변화 (대화 안 계산용, 실제 적용은 서버 파일)
        need: {npc: teacher, min: 50}        # 이 호감도 이상일 때만 보임
        event: c_wake_1        # 서버 명령 연결용 이름
    next: ""                   # 선택지가 없을 때 다음 장면 (비우면 대화 끝)
```

### 이름 규칙 (모드·서버·편집기 모두 같은 규칙)

- 대화 id(폴더 이름), 장면 id(`scenes` 의 키), 이벤트 이름(`event`): 소문자·숫자·`_`·`-` 로 1~64자 — 정규식 `[a-z0-9_\-]{1,64}`. 서버 플러그인과 같은 규칙이다.
- 규칙에 안 맞으면 대화를 열지 않고 채팅에 어느 키가 문제인지 알려 준다 (예: `장면 id 형식 오류: scenes.장면1`, `이벤트 이름 형식 오류: scenes.wake.choices[1].event`). 예전처럼 조용히 버리지 않는다.
- 숫자 자리(`need.min`/`need.max`, `affinity` 의 `add`)에 NaN·무한대가 오면 오류. 한 장면의 선택지가 6개를 넘으면 오류. 대사 한 줄이 1500자를 넘으면 오류 (나눠 쓸 것).
- 세 곳이 쓰는 정규식 (한쪽을 바꾸면 모두 바꿀 것):

  | 대상 | 정규식 | 검사하는 곳 |
  |---|---|---|
  | 컷신 id · 대화 id · 장면 id · 이벤트 이름 · 서버 파일의 `events`/`endings` 키 | `[a-z0-9_\-]{1,64}` | 모드 `DialogueParser.ID_PATTERN` / `CutsceneLoader.ID_PATTERN`, 서버 `StorySafety.ID`, 편집기 `ID_RE` |
  | NPC id (호감도 키, `npcs`) | `[^\s,=]{1,48}` (공백·쉼표·`=` 없이 48자까지, 한글 가능) | 서버 `StorySafety.NPC` |
  | 그림 파일 이름 | 경로 글자(`/` `\` `..`) 없이 `.png` 로 끝남 | 모드, 편집기 |

- 서버도 `dialogues/<id>/dialogue.yml` 을 같은 규칙으로 읽는다. 어긋나면 그 대화를 등록하지 않고 콘솔에 어느 키가 문제인지 적는다 (`/서버관리 새로고침 스토리` 때도).
- 편집기는 불러올 때 규칙에 안 맞는 장면 id·이벤트 이름을 보여 주고 "자동으로 고쳐서 불러오기" 를 물어본다 (이어지는 장면, 서버 명령어의 이름도 같이 바뀜). 내보낼 때도 검사한다.
- yml 에서 `yes` `no` `on` `off` `true` `false` `null` 이나 숫자만으로 된 이름은 따옴표가 없으면 다른 값으로 읽히므로 쓰지 말 것 (편집기는 모든 이름·글자를 따옴표로 감싸서 내보낸다).
- **이벤트 이름은 한 번 정하면 바꾸지 말 것.** 서버의 "이미 실행함" 기록이 이름으로 남는다. 편집기는 선택지마다 이름을 한 번 붙이면 순서를 바꾸거나 다른 선택지를 지워도 그대로 둔다 (불러온 파일의 이름도 그대로).
- 한 장면에 이벤트 이름이 없는 선택지가 둘 이상이고 `affinity` 가 서로 다르면, 둘이 (redirect·대사 없는 장면을 거쳐서라도) 같은 장면에 닿을 때 서버가 어느 쪽을 골랐는지 알 수 없어 뒤의 `need` 판정이 클라와 어긋날 수 있다 (서버 콘솔에 경고). 그런 선택지에는 `event` 를 붙일 것 — 편집기는 호감도나 명령어가 있는 선택지에 자동으로 붙인다.

### 대화창 (MagicCodex 대화창을 그대로 씀)

스토리 모드는 대화창을 직접 그리지 않는다. 대사·선택지·갈림길만 갖고 있고, **화면은 MagicCodex UI 모드의 NPC 대화창이 그린다** (게임 안 대화창은 한 가지).

- 필요한 것: MagicCodex UI 모드(mod id `magiccodex`) 중 `school.magiccodex.client.api.ExternalDialogue` 창구가 있는 버전 (`API_VERSION` 1 이상). 스토리 모드 jar 가 `depends` 로 요구하므로 없으면 게임이 켜질 때 알려 준다. 창구가 없는 옛 MagicCodex 면 대화를 열지 않고 채팅에 "스토리 대화를 보려면 MagicCodex 모드(최신 버전)가 필요합니다." 를 한 번 알린다 (자체 창으로 대신하지 않고, 끝 신호도 보내지 않는다).
- 모양·글꼴·타자기 속도·글자 소리·뒤 화면 어둡기는 MagicCodex 대화창을 따른다. `dim`, `type_speed`, `type_sound`, `type_sound_volume` 은 파일에 있어도 읽지 않는다 (오류 아님). 소리는 대화창 위의 "♪ 소리" 로 플레이어가 끈다.
- 조작: SPACE 또는 대화창 클릭 = 글자 바로 보기 → 다음. 긴 대사는 세 줄씩 나눠 넘어간다. 선택지는 클릭 또는 숫자키 1~6. "기록" 을 누르면 지나간 대사를 다시 볼 수 있다.
- 대사 한 줄 = 한 화면. 장면의 마지막 대사에 선택지가 붙는다. 선택지가 1개면 SPACE 로도 고를 수 있고, 2개 이상이면 고른 문장이 "내 차례"(내 일러스트 + 고른 문장)로 한 번 나온 뒤 다음 대사로 간다 (내 일러스트가 있을 때. NPC 대화와 같음).
- 왼쪽 위 제목 칸에 `title` 이 나온다.
- 표정 그림: PNG, 한 변 2048px·8MB 이하. 대화창 기준 화면(1600×900)에서 NPC 초상화와 같은 **700×1050 칸**(왼쪽 위 65,-5)에 비율을 지켜 맞추고, 가로는 가운데·세로는 칸 바닥에 붙인다. 대화 패널이 y=639 부터 덮으므로 **칸의 위쪽 약 61% 가 보인다**. MagicCodex NPC 초상화와 같은 2:3 (권장 1024×1536, 인물 상반신이 위쪽에 오게) 으로 만들면 같은 크기로 나온다. 그림 파일이 없으면 그림 없이 진행한다.
- 글자 수: 이름표 64자, 선택지 140자, 제목 140자를 넘으면 잘린다.

### 호감도 바꾸기

편집기에서 네 곳에 "+ 호감도"로 넣을 수 있다. 인물마다 한 줄, 올리면 +, 내리면 -.

| 언제 | 편집기 위치 | 한 번에 |
|---|---|---|
| 선택지를 고르면 | 선택지 ⚙ → "고르면 호감도 바꾸기" (여러 명 가능) | ±20 |
| 장면에 들어오면 | 장면 고급 → "이 장면에 들어오면 호감도 바꾸기" (대화마다 한 번) | ±20 |
| 이 장면에서 대화가 끝나면 | 장면 고급 → "여기서 대화가 끝나면 호감도 바꾸기" (결말 보상) | ±50 |
| 대화가 끝나면 항상 | 맨 아래 "대화가 끝나면 항상 바꿀 호감도" | ±50 |

- 클라 `dialogue.yml` 에는 선택지·장면의 `affinity: [{npc, add}, ...]` 가 들어가고 (대화 안에서 조건·갈림길 계산용),
  **실제로 점수를 바꾸는 값은 서버 `server_commands.yml` 의 `affinity:`** 이다. 클라 파일을 고쳐도 점수는 안 바뀐다.
- **호감도 한도 (한 항목)**: 선택지·장면 이벤트 ±20, 결말·끝 ±50 — 편집기, 모드(대화 안 계산), 서버가 모두 같은 숫자를 쓴다. 서버 파일에 더 큰 값을 적으면 읽을 때 한도로 자르고 콘솔에 경고한다.
- `need` / `redirect` 는 "대화를 열 때 서버가 보낸 호감도 + 지금까지 지나온 `dialogue.yml` 의 `affinity`" 로 계산한다. 서버도 같은 계산을 따라가며 검증하므로 `dialogue.yml` 과 `server_commands.yml` 의 값은 같게 둘 것 (편집기는 항상 같게 내보낸다).

```yaml
affinity:
  end: {teacher: 1}              # 대화가 끝나면 항상
  endings:
    go_friend: {teacher: 5}      # 이 장면에서 끝났을 때만
  events:                        # 선택지(c_장면_번호) / 장면 들어옴(e_장면) — 대화마다 한 번
    c_wake_1: {teacher: 2}
    c_wake_2: {teacher: -1, rin: 1}
```

### 닫기와 이어서 보기

- 스토리 대화는 마지막 대사(또는 선택지로 이어진 마지막 장면)가 끝날 때까지 닫을 수 없다. 대화창에 "닫기 ×" 가 없고, ESC 는 대화를 닫는 대신 게임 메뉴를 연다 (언제든 접속을 끊을 수 있게). 게임 메뉴나 다른 화면이 닫히면 보던 대사가 그대로 다시 열린다.
- 스토리 대화 중에 온 MagicCodex NPC 대화는 스토리 대화가 끝난 뒤에 열린다. 스토리 대화가 열릴 때 NPC 대화창이 떠 있었다면 그 대화는 닫힌다.
- 서버가 연 대화는 보고 있던 장면·대사 번호를 서버 `progress.yml` 에 저장한다. 접속이 끊기거나 서버가 재시작돼도 다시 접속하면 그 대사부터 이어서 열린다.
- 이미 실행된 이벤트(선택지 명령·호감도, 장면 들어옴 호감도)는 이어서 볼 때도, 대화를 다시 열어도 다시 실행되지 않는다 (플레이어별 완료 기록).
- 한 사람에게는 한 번에 하나만 재생된다. 대화 중에 온 다른 대화·컷신 (또는 컷신 중에 온 대화) 은 순서대로 기다렸다가 앞의 것이 끝나고 그 끝 명령이 실행된 다음에 열린다.
- **이미 끝낸 대화**를 다시 열라는 명령은 아무 일도 하지 않는다 (콘솔에 안내만). 다시 보여 주려면 `/테스트 스토리 대화 <대화id> <닉네임>`(미리보기, 보상 없음), 또는 config `allow-replay: true` / 그 대화 `server_commands.yml` 의 `allow-replay: true`. 다시 보기는 명령어·호감도를 다시 주지 않는다.
- 강제로 끝내기: `/대화관리 중지 <닉네임>` (끝 명령은 실행되지 않고 완료로 기록되지 않음). 완료 기록 보기·지우기: `/유저관리 <닉네임> 스토리기록 보기 [대화id]`, `/유저관리 <닉네임> 스토리기록 초기화 <대화id|전체> 확인`.

### 대사에 쓸 수 있는 글자

| 글자 | 바뀌는 값 |
|---|---|
| `{player}` | MagicCodex 에서 정한 **한글 닉네임** (칭호 없이). 없으면 마인크래프트 닉네임 |
| `{account}` | 마인크래프트 닉네임 |
| `%플레이스홀더%` | 서버 config `dialogue-placeholders` 에 적어 둔 PlaceholderAPI 값. 예: `%chacademiatitle_full%` (칭호 붙은 이름) |

이름표, 대사, 선택지 글 어디서나 쓸 수 있다. 서버 없이 `/story dialogue` 로 혼자 열 때는 `{player}` 만 이 PC 의 MagicCodex 모드에서 가져온다.

### "나"의 그림

- 화자 id 가 `me` 이면 (편집기의 "나 (플레이어)") MagicCodex UI 모드가 받아 둔 **ChacaPortrait 내 일러스트**를 MagicCodex 대화창이 "내 차례"와 같은 자리·크기로 그린다.
- 일러스트를 서버에 따로 요청하거나 새로 만들지 않고, MagicCodex 가 이미 가진 것을 그리기만 한다 (ChacaPortrait 와 충돌 없음).
- 아직 일러스트가 없으면, `me` 에 넣은 표정 그림 → 그것도 없으면 앞 사람 그림을 그대로 둔다.

## server_commands.yml (서버)

```yaml
npcs: [teacher]      # 이 대화에 나오는 NPC (편집기가 자동으로 적음). 대화를 열 때 이 NPC 들의 호감도를 보냄
end:                 # 어느 결말이든 대화가 끝나면
  - "대화관리 재생 {player} 대화 ch1_school"
endings:             # 이 장면에서 끝났을 때만
  wake_friend:
    - "say {player} 님은 선생님과 친해졌습니다"
events:              # 이 이벤트가 있는 선택지를 고르면 (플레이어마다 대화당 한 번)
  c_wake_1:
    - "give {player} bread 1"
allow-replay: false  # (선택) 이미 끝낸 사람에게 다시 보여 줄지. 없으면 config 의 allow-replay 를 따름
```

쓸 수 있는 글자: `{player}` 마인크래프트 닉네임 (명령어 대상용), `{nickname}` 한글 닉네임, `{uuid}`, `{id}` 대화 id, `{scene}` 마지막 장면 id, `{event}` 이벤트 이름.

- `{nickname}` 은 플레이어가 정한 글자라서 명령어에 넣기 전에 글자·숫자·`_`·`-` 만 남기고 32자에서 자른다 (공백·따옴표·`@`·줄바꿈으로 명령어를 바꿔치기하지 못하게). 남는 글자가 없으면 마인크래프트 닉네임을 쓴다.
- 명령어는 한 줄씩, 한 목록에 64개까지. `events` / `endings` 의 키는 이름 규칙을 따른다 (어긋나면 무시하고 콘솔 경고). `dialogue.yml` 에 없는 이벤트·장면을 적으면 콘솔에 경고한다 (실행될 일이 없음).

## 호감도

- **MagicCodexBridge 가 켜져 있으면 MagicCodex 가 저장한다.** ChacaNPC AI 대화와 같은 점수이고, MagicCodex 의 하트 단계 상한(하트 이벤트 전에는 20×(단계+1)점에서 멈춤)이 그대로 적용된다. 출처 이름은 `dialogue`.
- MagicCodexBridge 가 없으면 이 플러그인이 `plugins/ChacademyStory/affinity.yml` 에 따로 저장한다 (기록이 없으면 25).
- 대화를 열 때 서버가 `npcs` 에 적힌 NPC 의 현재 호감도를 모드로 보내 준다. 모드에 값이 없으면 25 로 본다.
- 실제 호감도는 서버 파일에 선언한 이벤트·결말·끝 값만 적용한다 (한 항목 한도: 이벤트 ±20, 결말·끝 ±50). MagicCodex 연결 시 그 서비스의 하트 단계·출처별 일일 한도가 추가로 적용된다.
- config `affinity-gain-cap-per-dialogue` (기본 0 = 끔): 한 플레이어가 한 대화에서 얻는 호감도 (오른 것만, 모든 NPC 합) 의 상한. 예전의 `affinity-max-per-dialogue` 는 쓰지 않는다.
- `affinity.yml`, `progress.yml` (진행·완료 기록) 은 **그 서버만의 파일**이다. 서버가 여러 대면 MagicCodexBridge 로 호감도는 같이 쓰지만 진행·완료 기록은 서버마다 따로다 → 보상을 주거나 퀘스트를 넘기는 스토리 명령은 한 서버에서만 실행되게 할 것 (같은 대화를 두 서버에서 열면 서버마다 한 번씩 보상이 나간다).
- (2026-10-20) 스토리 플러그인의 예비 호감도(`affinity.yml`)는 삭제됐다. 호감도는 MagicCodex에서만 관리한다.
- 명령어: `/affinity <플레이어> [npc] [set|add] [값]` (별칭 `/호감도`)


## 서버 검증 · 기록 · 보호

- **흐름 검증**: 서버는 `dialogues/<id>/dialogue.yml` 을 읽어 두고 (서버를 켤 때와 `/서버관리 새로고침 스토리` 때만 파일을 읽는다) 모드가 보낸 신호가 실제로 가능한지 따라가며 본다.
  - 진행(`dialogue_progress`): 지금 장면 안의 줄이거나, 지금 장면에서 갈 수 있는 다음 장면이어야 한다 (`next`, 보이는 선택지의 `to`, `redirect` 를 서버 쪽 호감도로 계산).
  - 이벤트(`dialogue_event`): 지금 고를 수 있는 선택지의 이벤트이거나 들어가는 장면의 이벤트여야 한다. **선택지 이벤트는 장면을 한 번 방문할 때 하나만** 인정한다. `need` 를 만족하지 않는 선택지는 고를 수 없다.
  - 끝(`dialogue_done`): 실제로 대화가 끝날 수 있는 장면이어야 한다.
  - 어긋난 신호는 무시하고 센다. 한 번의 대화에서 20개가 넘거나, 인정할 수 없는 "끝" 신호가 오면 (클라는 이미 창을 닫았으므로) 바로 대화를 멈추고 콘솔에 경고한다 (클라의 대화 파일이 서버와 다르거나 조작된 클라). 다음 접속 때 다시 열린다. config `story-debug: true` 면 하나씩 기록한다.
  - 스토리 채널의 패킷은 플레이어마다 초당 20개 (순간 40개) 까지만 읽고 나머지는 버린다.
- **완료 기록 (progress.yml, format 2)**: 플레이어마다 재생 중·대기 중인 컷신/대화, 끝낸 대화, 대화별로 이미 실행한 이벤트, 저장은 됐지만 아직 실행하지 못한 효과를 담는다. 서버가 켜져 있을 때 직접 고치지 말 것.
  - 효과(명령어·호감도)는 **기록을 디스크에 쓴 다음** 실행한다. 쓰기에 실패하면 실행하지 않고 2초마다 다시 쓴다. 플레이어가 그 사이에 나갔으면 다음 접속 때 실행한다.
  - 실행한 효과를 목록에서 지우는 저장이 끝나기 전에 서버가 강제로 죽으면, 그 효과는 다음 접속 때 한 번 더 실행될 수 있다 (누락되지는 않는다). 명령어 실행 중 오류가 난 효과는 다시 실행하지 않는다.
  - 파일 쓰기는 전용 스레드가 하고 (임시 파일 → 바꿔치기), 같은 틱의 변경은 한 번에 쓴다. 서버가 꺼질 때만 그 자리에서 쓴다. 대사 위치는 5초마다 모아서 저장하므로 강제 종료 때 조금 되돌아갈 수 있다.
  - 예전 형식(format 없음: 진행 중인 대화만)은 처음 켤 때 자동으로 옮기고 원본을 `progress.yml.v1-backup` 으로 남긴다.
- **모드가 없거나 오래된 플레이어**: 접속 뒤 15초까지 모드 채널을 기다린 다음에만 "모드 없음" 으로 본다 (접속하자마자 온 스토리 명령도 기다렸다가 재생). config `finish-if-missing-mod` 기본값은 `false` — 스토리가 넘어가지 않고, 모드를 넣고 다시 접속하면 이어진다. `true` 면 보지 않고도 끝 명령·끝 호감도를 받으므로 (모드 채널은 클라가 정함) 끝 명령이 보상을 주는 서버에서는 켜지 말 것.
- **클라가 보여 줄 수 없을 때** (대화·컷신 공통): 파일이 없거나 깨졌거나 (이름 규칙 위반 포함), 대화는 MagicCodex 대화창을 쓸 수 없으면 모드가 끝 신호 대신 `story_fail` 을 보낸다. 서버는 끝난 것으로 치지 않고 콘솔에 경고를 남기며 그 요청을 멈춰 둔다. 파일(모드)을 맞추고 다시 접속하거나 `/서버관리 새로고침 스토리` 하면 다시 시도하고, 관리자가 `/대화관리 중지` / `/대화관리 대기열비우기` 로 치울 수 있다.
- **보는 동안 보호** (config `protect-during-story: true`): 재생 신호를 보낸 때부터 끝·중단·종료까지 피해를 받지 않고 (낭떠러지 밖·`/kill` 제외), 몹이 노리지 않고, 배고픔이 줄지 않고, 수평으로 제자리에 고정된다 (떨어지는 것은 막지 않음, 물약 효과 없음). 사망·접속 종료·월드 이동 때 풀리고, `protect-max-seconds` (기본 900초) 가 지나면 끝 신호가 없어도 풀린다.
- **컷신 최소 시간** (config `min-seconds.<컷신id>`): 그보다 빨리 끝났다고 오면 인정하지 않고 다시 재생한다. 2배속이 있으므로 길이의 절반보다 작게 적을 것.

## 서버와 주고받는 신호 (프로토콜 2)

플러그인 채널 `chacademy:<이름>`. 문자열 = VarInt(UTF-8 바이트 수) + UTF-8, 정수 = VarInt, 참거짓 = 1바이트. 모드(`CutscenePackets`)와 플러그인(`StoryCodec`)이 같은 형식을 따로 구현한다 (모드 테스트가 둘을 맞대어 본다).

| 방향 | 채널 | 내용 | 뜻 |
|---|---|---|---|
| 서버→클라 | `story_v2` | 버전(VarInt) | 서버 프로토콜 버전. **모드가 이 채널을 듣는 것이 "프로토콜 2" 라는 표시** |
| 서버→클라 | `cutscene_play` | id, 모드(0 auto·1 skip·2 noskip) | 컷신 재생 |
| 서버→클라 | `cutscene_stop` | (없음) | 컷신 멈춤 (끝난 것 아님) |
| 클라→서버 | `cutscene_done` | id, 건너뜀(참거짓) | 끝까지 봄 / 건너뜀 |
| 클라→서버 | `cutscene_abort` | id | 끝나기 전에 화면이 사라짐 → 서버가 다시 보냄 **(새로 추가)** |
| 클라→서버 | `story_fail` | 종류(0 컷신·1 대화), id, 이유 | 보여 줄 수 없음: `missing` 파일 없음 · `broken` 읽을 수 없음 · `timeout` · `magiccodex` 대화창 없음 **(새로 추가)** |
| 서버→클라 | `dialogue_open` | id, 호감도 `npc=점수,…`, 글자 바꾸기 목록, 시작 장면, 시작 줄 | 대화 열기 (시작 장면이 있으면 이어서) |
| 서버→클라 | `dialogue_stop` | (없음) | 대화 닫기 |
| 클라→서버 | `dialogue_progress` | id, 장면, 줄 | 지금 보는 곳 (줄이 넘어갈 때마다, 장면에 들어갈 때마다) |
| 클라→서버 | `dialogue_event` | id, 이벤트 이름, (안 씀: npc, 4바이트 정수) | 선택지를 고름 / 이벤트가 있는 장면에 들어감 |
| 클라→서버 | `dialogue_done` | id, 마지막 장면 | 대화 끝 |

- **버전 확인**: 서버는 플레이어가 듣는 채널 이름에서 버전을 읽는다 (`story_v<숫자>` 가운데 가장 큰 값, 없고 `cutscene_play` 만 들으면 1 = 예전 모드). 2보다 낮으면 스토리 패킷을 보내지 않고 "차카데미 스토리 모드가 오래된 버전입니다. 모드를 업데이트해 주세요." 를 보낸다 (config `outdated-mod-message`). 예전부터 있던 패킷의 바이트 형식은 바꾸지 않았다.
- 새 모드가 예전 플러그인에 접속하면 (서버가 `story_fail` 을 모름) 컷신 파일이 없을 때 예전처럼 "건너뜀" 으로 알린다.
- 문자열 길이: 클라→서버는 256자 (UTF-8 768바이트) 까지 — 모드가 보내기 전에 자르고 서버는 넘으면 패킷을 버린다. 서버→클라는 32767자까지. 클라→서버 패킷 하나는 2048바이트까지.
- 모드가 지켜야 하는 순서: 장면에 들어가면 (이벤트가 있으면 `dialogue_event` →) `dialogue_progress(장면, 0)`, 줄이 넘어가면 `dialogue_progress(장면, 줄)`, 선택지를 고르면 그 선택지의 `dialogue_event` 를 보낸 다음 들어간 장면을 알린다. 이어서 볼 때는 redirect·진입 이벤트 없이 `dialogue_progress(시작 장면, 시작 줄)` 부터.
- 서버는 `dialogue_open` 을 보낼 때의 호감도에서 시작해 모드와 같은 규칙 (redirect, 장면 진입 `affinity` 는 장면마다 한 번, 대사도 선택지도 없는 장면은 `next` 로 통과, 20번 넘게 이어지면 끝) 으로 따라간다. 모드의 진행 규칙을 바꾸면 플러그인 `StoryGraph.Walk` 도 같이 바꿀 것.

## Optional journal chapter

Top-level `chapter: "제1장"` groups a story journal entry below its category. Omit it to keep the previous flat journal behavior. `title` and `description` retain their existing meanings; chapter does not alter scene IDs, progression, rewards or affinity receipts.
