# 차카데미 스토리

## 설치와 기본 동작

- 클라이언트에 최신 스토리 모드와 MagicCodex UI를 함께 설치한다. 기존 같은 모드의 중복 버전은 제거한다.
- 컷신은 `config/chaca_cutscene/<id>/cutscene.yml`, 대화는 `config/chaca_dialogue/<id>/dialogue.yml`에 둔다.
- 기본 대화 재생은 클라이언트 파일 한 벌을 사용한다. 서버에 대화 그래프나 종료 명령 파일을 복사할 필요가 없다.
- 종료·이벤트 명령은 같은 `dialogue.yml`의 `commands.end`, `commands.endings`, `commands.events`에 둔다. 일반 명령은 플레이어 권한으로 실행한다. 기존 두 고정 보상 연결만 예외이며 임의 콘솔 실행 경로는 없다.
- 완료·보상 중복 방지 기록은 클라이언트 `config/chaca_dialogue/_progress/<계정 UUID>.properties`에 저장된다. 재생·리로드로 초기화하지 않는다. 완료한 대화를 다시 볼 수 있지만 효과는 반복하지 않는다.
- 닉네임 대상 해석에는 최신 MagicCodexBridge가 필요하다. 기존 Bridge에서는 영문 계정명을 사용한다.

## 관리자 명령 (MagicCodexBridge 명령어 허브, OP 전용)

| 명령 | 동작 |
|---|---|
| `/대화관리 재생 <닉네임\|모두> 대화 <ID>` | 대상 클라이언트 대화 파일 재생 요청 (콘솔 가능) |
| `/대화관리 재생 <닉네임\|모두> 컷신 <ID> [건너뛰기허용\|건너뛰기금지\|자동]` | 컷신 재생 요청 (대기열 순서대로, 끝나면 `on-finish`) |
| `/대화관리 중지 <닉네임\|모두>` | 지금 보는 스토리 멈추기 (끝 명령 없음) |
| `/대화관리 대기열비우기 <닉네임\|모두>` | 재생 중·대기 중인 것 모두 취소, 완료 기록 유지 |
| `/대화관리 목록 [닉네임]` | 재생할 수 있는 대화·컷신 ID |
| `/대화관리 클라이언트새로고침 [닉네임]` | 대상 클라이언트의 대화·컷신 파일 다시 읽기 |
| `/유저관리 <닉네임> 스토리기록 보기 [대화]` | 이 서버의 진행·완료 기록 |
| `/유저관리 <닉네임> 스토리기록 초기화 <대화\|전체> 확인` | 완료 기록 지우기 |
| `/테스트 스토리 대화 <ID> [닉네임]` · `/테스트 스토리 컷신 <ID> [닉네임]` | 조건·기록 무시 미리보기 (보상·끝 명령 없음, 이미 본 것도 다시 보임) |
| `/서버관리 새로고침 스토리` | 서버 config.yml + `dialogues/server_command.yml` + 서버 대화 파일 다시 읽기 |

`모두`는 접속자 전체. 닉네임은 접속 중인 유저만 (못 찾으면 알림). 호감도는 MagicCodex 하나로만 관리한다 (스토리 플러그인 자체 `affinity.yml`·`/affinity` 없음, `/유저관리 <닉네임> 호감도`).

## 내 클라이언트에서 사용하는 명령 (개발용)

- `/스토리도구 재생 <ID>` (대화 또는 컷신), `/스토리도구 대화 <ID>`, `/스토리도구 컷신 <ID>`
- `/스토리도구 목록`, `/스토리도구 새로고침`, `/스토리도구 본기록초기화` (본 컷신 기록만)

새로고침은 파일을 다시 읽어 검사할 뿐 현재 대화를 중단·교체하지 않고, 명령·보상 실행이나 완료 기록 쓰기를 하지 않는다. 자동완성은 접속 시와 새로고침 때 수집한 ID 목록(종류별 최대 128개)을 쓴다.

예전 명령 `/cutscene` `/컷신` `/storydialogue` `/스토리대화` `/스토리` `/affinity` `/호감도`, 클라이언트 `/story` `/컷신도구` `/ccs`는 삭제됐다. 서버 설정 안의 명령 문자열은 새 명령으로 바꿔야 한다 (예: `storydialogue {player} ch1-2` → `대화관리 재생 {player} 대화 ch1-2`).

## 빌드

호스팅 Java 21에서 스토리 모드 `test remapJar`, 스토리 플러그인 `test jar`, Bridge `test jar`를 실행한다. 개인 배포 글꼴은 외부 경로의 기존 글꼴을 사용하며 공개 소스에 포함하지 않는다.
