# Magic Codex Bridge 0.4.1

Paper 1.21.4 / Java 21용 **권한 확인 전용 플러그인**이다. 클라이언트의 Magic Codex 0.4.1과 함께 사용한다. YAML·아이콘·UI는 클라이언트에 있고 서버에는 설치하지 않는다. 권한 지급·회수 명령, 마법 실행, 기증 기능은 포함하지 않는다.

## 설치

1. 서버의 `plugins/`에 `magic-codex-bridge-0.4.1.jar`를 넣고 서버를 정상 재시작한다.
2. 클라이언트의 기존 도감 JAR를 `magic-codex-ui-0.4.1+mc1.21.4.jar`로 교체한다. Fabric API는 계속 필요하다.
3. 클라이언트의 `config/magiccodex/spells/`는 그대로 사용한다.
4. `/UI`를 열면 각 YAML의 `permission`을 서버에서 확인하여 발견·미발견으로 표시한다. 보유 권한이 없는 마법의 발견 조건은 숨긴다.

LuckPerms는 선택 사항이다. 설치되어 있으면 권한 변경 알림을 활용한다. 서버의 `Player.hasPermission` 결과를 그대로 사용하므로 그룹 상속·부정 권한·와일드카드·OP 및 기본 권한 규칙이 적용된다. 실제 습득 확인은 일반 플레이어 계정으로 점검하는 것이 정확하다. 이 플러그인이 권한을 새로 부여하지는 않는다.

## 서버 부담을 제한하는 방식

- 도감을 열 때 로컬 YAML에서 중복을 제거한 권한 이름만 한 번 보낸다. 최대 256개다.
- 서버는 도감 구독자만 관리한다. 닫기·접속 종료 시 구독과 결과 캐시를 제거한다.
- 첫 OPEN 요청은 다음 서버 틱에 처리하도록 예약한다. 같은 틱의 여러 OPEN은 하나의 작업으로 합친다. 이후 활성 구독을 1초마다 관리한다. LuckPerms 변경 알림은 플레이어별로 합쳐 처리하며, Bukkit API는 서버 메인 스레드에서만 호출한다.
- 일반 권한 변경도 반영하도록 열려 있는 도감만 기본 10초 간격으로 보조 확인한다. 전체 접속자나 전체 등록 권한을 순회하지 않는다.
- 기본 작업 상한은 1초 구간당 권한 조회 2,048번이다. 첫 요청의 즉시 작업과 정기 작업이 같은 조회 한도를 공유한다. 초과분은 다음 순서로 넘겨 한꺼번에 몰리지 않게 한다. 256개씩 조회하는 20명의 동시 요청을 상한 안에서 나눠 처리하는 자동 검사를 통과했다.
- 마지막 결과와 같으면 전송하지 않는다. 결과를 비트로 묶어서 18개 마법은 17바이트, 최대 256개는 46바이트다. 게임 패킷 헤더는 별도다.
- 열린 도감은 15초마다 13바이트 유지 신호만 보낸다. 이 신호는 권한 조회를 유발하지 않는다. 닫기 신호가 없어도 기본 45초간 유지 신호가 없으면 구독을 만료시킨다.
- OPEN 요청은 플레이어별 1초에 1회까지만 파싱하고, 잘못된 길이·중복 권한·허용되지 않은 문자·잘못된 버전을 거부한다.

권한 변경 반영은 LuckPerms 알림이 있으면 다음 처리 주기, 알림이 없는 변경은 보조 확인 주기에 이루어진다. 작업량이 상한에 도달하면 더 늦어질 수 있다. 접속자 수에 따른 실제 TPS 영향은 부하 테스트로 측정한 수치가 아니다.

## 설정

처음 시작하면 `plugins/MagicCodexBridge/config.yml`이 생성된다. 변경 후 서버를 재시작한다.

```yaml
refresh-interval-ticks: 200
max-permission-checks-per-pass: 2048
session-timeout-seconds: 45
```

확인 주기는 20~1,200틱, 작업 상한은 256~16,384회, 만료 시간은 30~120초 범위로 제한한다. 서버 TPS가 낮으면 실제 반영 시간이 길어질 수 있다. 기본값으로 시작하는 것을 권장한다.

## 상태와 범위

최초 권한 확인 전에는 회전 문양과 로딩 안내를 표시하고 카드 조작을 잠근다. 응답이 도착하면 0.18초 페이드로 실제 도감을 표시한다. 서버 연결이 없거나 지연되면 안내 문구를 표시하며 ESC와 X로 닫을 수 있다. 도감을 닫거나 연결이 바뀌면 클라이언트의 확인 결과를 지우고 다시 열 때 새로 확인한다. `/UI reload`로 목록이 바뀌어도 이전 요청의 응답은 새 목록에 적용하지 않는다. 권한 결과는 UI 표시용이며 실제 마법 실행 권한 검사는 이후 실행 기능의 서버 처리에서도 필요하다.

현재 제공되는 숨김은 도감 화면에서의 표시 제어다. YAML 파일 자체는 기존 설계대로 클라이언트에 배포한다.

## 검증 및 빌드

Paper API 1.21.4 및 LuckPerms API 5.4를 대상으로 컴파일했다. 플러그인 자동 검사 15개와 모드 자동 검사 51개가 통과했다. 처리 상한·변경 전송·회수·닫기·만료·중복 요청·잘못된 패킷·오래된 응답 차단을 검사했다. 모드의 로딩 화면 및 확인 전 카드 조작 차단도 별도 개발 클라이언트에서 확인했다. Paper와 Fabric을 실제로 접속시킨 응답 시간 측정은 수행하지 않았다.

소스 ZIP의 `magic-codex-paper`, `magic-codex-fabric`, `magic-codex-protocol`을 같은 상위 폴더에 둔다. 각 프로젝트에서 Java 21로 `gradlew.bat build`를 실행한다. 공통 프로토콜은 양쪽 JAR 안에 각각 포함되어 별도 설치하지 않는다. Paper·LuckPerms API는 배포 JAR에 포함하지 않는다.

사용 API: [Paper plugin messaging](https://docs.papermc.io/paper/dev/plugin-messaging/), [LuckPerms 이벤트 API](https://luckperms.net/wiki/Developer-API-Usage).
